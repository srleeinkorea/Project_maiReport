한눈에 보기

이 문서가 다루는 것홈에 처음 들어온 순간부터 질문에 답하고, 코칭과 목표가 생기고, 타일을 완료하고, 답을 고치는 데까지 화면이 어떻게 이어지는지. 3장의 왼쪽 화면은 직접 눌러 볼 수 있음. 데이터는 모두 가상임.
가장 중요한 결정화면 이동이 없음. 질문 카드 하나가 글과 버튼만 바꾸며 이어지고, 마지막 답에서 코칭 카드와 잠긴 타일이 같은 화면 안에서 바뀜. 답변 보기만 별도 화면임.
아직 정해지지 않은 것10-14에 5건을 결정해 닫았음. 남은 것 없음. 자세한 내용은 「확인 필요」.
01

흐름 개요

시작끝거치는 화면
그날 첫 홈 진입(새벽 4시 이후 처음)코칭 1 + 목표 3이 보이는 홈. 타일 완료는 하루 동안 이어짐홈(식사 질문) → 홈(식사 시각) → 홈(식이 회전 질문) → 홈(보완 질문) → 홈(완료 카드 · 코칭 생성 중) → 홈(코칭 · 목표) → 답변 보기 → 홈(코칭 재생성)

질문 수는 시나리오마다 다름. 워치 사용자가 점심에 들어오면 4문항, 아침 8시(어제 저녁 질문 · 시각 없음)는 3문항, 결식 답이면 2문항이 됨.

04

분기와 예외

상황화면다음
식사 질문이 「어제 저녁」(04~10시 · 00~04시)시각 질문을 내지 않음. 진행 표시는 1/3처럼 처음부터 작게식사 답 → 회전 질문
식사 답이 「못 먹거나 거름」시각 · 회전 질문이 빠지고 N이 줄어듦(1/4 → 2/2). 식이 목표는 회복 풀보완 질문 또는 완료
17~24시 「오늘 저녁」 질문카드 아래 「오늘 저녁을 드신 뒤 답해주세요」. 답하기 전까지 회전 질문과 식이 목표가 기다림저녁 먹은 뒤 답 → 시각 → 회전 → 식후 목표
일부만 답하고 나감코칭 「답변 전」, 잠긴 타일 유지. 재진입 시 끼니 구간이 넘어갔으면 미답 식이 문항의 끼니 이름만 갱신남은 문항부터
답 저장 실패선택 상태를 유지하고 재시도. 다음 문항으로 넘어가지 않음성공 후 다음
잠긴 타일 탭질문 영역으로 스크롤해 남은 문항을 보여 줌. 생활 탭에서 눌렀으면 홈으로남은 문항
식이 후보가 하나도 없음식이 타일이 안내 상태 「오늘은 개인 식사 계획을 먼저 확인해 주세요」. 완료 버튼 없음, n/3 분모 제외—
목표 일부를 완료한 뒤 답을 마침완료 타일은 그대로, 대기 타일만 답으로 바뀜. 대기 타일 위에 「답변을 반영해 목표를 새로 추천했어요」 1회—
3개 모두 완료한 뒤 답을 마침타일은 그대로, 코칭만 생성—
답변 보기에서 답 수정코칭 「생성 중」 → 새 결과. 답변으로 만든 목표 중 완료하지 않은 것만 다시 생성. 기기 데이터로 만든 목표와 완료한 목표는 불변홈 ⑥
코칭 생성이 늦거나 실패「생성 중」은 최대 5초. 넘기면 답변만으로 정할 수 있는 식이 기본 문구를 먼저 보여 주고 응답이 오면 조용히 바꿈⑥
건강 데이터 미연동질문 · 코칭 · 목표는 정상. 활동 목표는 기록 없이도 안전한 기본 문구(「점심 식후 10분 걷기」)로 바로 열리고, 수면 목표만 잠겨 수면 문항으로 보완—
진료정보에 미확인 질환첫 식이 문항이 「{질환명}을 진단받았거나 관리 중이신가요?」로 바뀜. 「네」면 그 질환의 회전 질문, 아니면 공통 식사 질문. 하루 최대 1개식이 질문 2개 안에서 처리
05

데이터와 연동

단계주고받는 것외부 호출 · 저장
첫 진입앱이 보냄: 사용자 · 진입 시각 · 시간대. 서버가 읽음: 오늘 문항 상태, 기기 데이터(오늘 걸음 · 어젯밤 수면), 직접 선택 질환, 진료정보 확인 상태, 3개월 이내 검진, 식이 28일 답, 축 단계, 최근 30일 목표. 돌려줌: 질문 계획(문항 목록 · 끼니 이름), 목표 3개의 열림/잠김과 열린 목표의 문구건강 앱 읽기(삼성헬스 · 애플헬스). 목표 기록 열린 것 저장(출처 = 기기)
① 식사 질문답 코드 · 끼니 날짜 · 끼니 종류 · 답한 시각답 이력 1행. 문항 상태 = 답함
② 식사 시각고른 버튼(범위) · 답한 시각. 식사 시각은 서버가 건강 앱 기록 → 선택지 범위의 가운데 순으로 정함답 이력에 시각 범위. 자기돌봄 지표의 식후 걸음 판정에 사용
③ 식이 회전축 · 답(좋음/중간/나쁨). 축 상태는 다음 날부터 반영, 오늘 문구 선택에는 오늘 답 사용답 이력 · 축 지표 스냅샷 재계산
④ 보완 질문피로감 · 수면 등 답. 지표 입력으로 채택할지는 미검증그날 답변 저장
⑤ 모두 답함앱이 생성 요청. 서버: 코칭 1건(답 + 기기 데이터), 잠긴 목표(식이: 축 → 단계 → 문구 → 대상 끼니, 활동 · 수면: 답 + 개인 중앙값)코칭 결과 1건. 목표 기록(출처 = 답변) 저장. 안내 상태면 문구 없이 안내로 저장
⑥ 타일 완료/취소카테고리 · 날짜 · 완료 여부목표 기록 갱신. 연속일수 · 주간 달성률은 카테고리 기준
⑦ 답 수정바뀐 답(현재 답 교체, 이전 답은 보존)코칭 재생성. 답변으로 만든 대기 목표 재생성

필드 이름과 테이블은 식이 개발 전달 데이터계약과 코칭목표 › 지식DB 전달테이블을 정본으로 함.

06

시나리오

52세 회사원, 워치 착용, 공복혈당 108 경계. 수요일.

  1. 오후 1시 10분, 점심 뒤 처음 앱을 엶. 워치가 어젯밤 수면 6시간 10분과 오늘 걸음 3,200을 보냈음. 활동 타일 「6,500걸음 걷기」와 수면 타일 「11시 반 전 잠자리」는 바로 열려 있고 식이 타일만 잠겨 있음. 코칭은 「먼저 오늘의 질문에 답하고…」. 진행 표시는 1/4.
  2. 「오늘 점심은 평소만큼 드셨나요?」에 「충분히 먹음」. 같은 카드가 「점심은 언제쯤 드셨어요?」로 바뀜. 버튼은 1시 10분을 기준으로 「1시간 이내」 「1~2시간 전」 「그보다 전」(각각 오후 12:10 이후 · 오전 11:10~오후 12:10 · 오전 11:10 전」 「오전 11:10 이전 · 그보다 전」. 첫 번째를 고름(2/4).
  3. 회전 질문. 혈당 경계라 연결 축(채소 · 단 음료 · 식사 속도) 중 28일 답이 가장 적은 채소가 나옴. 「오늘 점심엔 채소 반찬을 얼마나 드셨나요?」에 「조금 먹음」(3/4).
  4. 보완 질문. 워치가 모르는 피로감을 물음. 「보통이에요」(4/4).
  5. 모두 답함. 질문 카드가 완료 카드로 바뀌고 코칭 카드에 「생성 중」이 돎. 잠시 뒤 「점심 뒤 10분만 걸어 보세요」가 보이고, 식이 타일이 「한 끼는 채소 반찬 한 가지」(대상 끼니 오늘 저녁)로 열림. 활동 · 수면 타일은 그대로임.
  6. 오후 6시, 걸음이 7,100이 됐음. 활동 타일 숫자는 6,500 그대로이고 자동 완료도 없음. 사용자가 타일을 눌러 완료함. 「1/3 완료 ›」.
  7. 저녁 9시, 답변 보기에서 점심 답을 「적게 · 몇 입만」으로 고침. 코칭이 「생성 중」을 거쳐 「저녁은 가볍게, 11시 전 잠자리」로 바뀜. 식이 목표는 답변으로 만든 것이라 다시 고르고, 활동 목표는 기기로 만든 데다 완료했으니 그대로임.
  8. 다음 날 새벽 4시. 세트가 끝나고 완료 기록 1/3과 연속일수만 남음.

질문누가 정하나기한상태

보완 문항(피로감 · 수면 등)의 풀과 선정 규칙. 이 설계서의 보완 질문은 예시임기획활동 · 수면 기획 시닫힘(10-14) · 활동 3축 · 수면 3축의 축 × 단계 구조로 감. 문항 세트는 활동 · 수면 기획서에서
시각 버튼 순서(아침은 이른 시각부터, 점심 · 저녁은 최근부터)기획—닫힘(10-14) · 끼니마다 그대로 둠. 아침은 정각 고정이라 이른 시각부터, 점심 · 저녁은 답한 시각에서 거꾸로 세므로 최근부터가 자연스러움
시각 단계에서 앱을 나갔음 오면 버튼을 새 시각으로 다시 만들지기획—닫힘(10-14) · 식사 답은 두고 시각 버튼은 다시 들어온 시각 기준으로 새로 만듦
