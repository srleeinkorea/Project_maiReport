# JIRA 업무 등록 템플릿

판 1.0 · 2026-10-14. 프로젝트 MSO(의학전략실), 에픽 「maiReport 개선 작업」(MSO-90) 아래 이슈를 만들 때 쓴다.

## 1. 크기 규칙

- 이슈 하나 = **산출물 하나**, 영업일 5일 안에 끝나는 크기. 넘으면 하위 작업으로 쪼갠다.
- 산출물이 여러 개인 일(기능 하나를 설계 → 데이터 → 검토 → 배포까지)은 **부모 이슈 1 + 하위 작업 N**으로 등록한다. 부모는 목적·범위·완료 조건만 담고, 할 일은 하위 작업에 둔다.
- 「확인 필요」처럼 결정만 하는 일은 결정 항목 하나당 한 줄 체크리스트로 두고, 결정이 나면 체크하고 댓글에 날짜와 결정 내용을 남긴다.

## 3-1. 문체

본문은 격식을 갖춘 문어체로 쓴다. 처음 읽는 사람도 한 번에 이해할 수 있어야 하고, 외부에 그대로 공유되어도 문제가 없어야 한다.

**어조**
- 문장은 「~한다」「~로 한다」「~를 확정한다」로 끝맺는다. 「~해야 함」「~할 것」 같은 개조식 종결, 「~해요」 같은 구어체는 쓰지 않는다.
- 주어와 목적어를 생략하지 않는다. 「반영」이 아니라 「화면설계서에 반영한다」.
- 줄임말·은어·내부 별칭을 쓰지 않는다. 「정훈샘」은 「계산식 담당자」, 「깃헙」은 「GitHub 저장소」, 「샘플」은 「예시 화면」으로 쓴다. 사람은 역할로 지칭하고 이름은 담당자 필드에만 둔다.
- 「대충」「일단」「등등」「~인 듯」처럼 판단을 흐리는 표현을 쓰지 않는다. 미정이면 「확정 전」이라고 명시한다.
- 권장 어휘: 확정·수립·반영·검증·산출·고지·보류·이관·전달·정합성·근거·기준·범위·조건.

**법적으로 주의할 표현**
- 서비스 기능이 질병을 진단·치료·예방한다고 읽히는 표현을 쓰지 않는다. 「혈당을 낮춘다」가 아니라 「식후 활동을 제안한다」. AI 결과는 「참고 정보」「보조 결과」로 쓴다.
- 의학적 효과를 단정하지 않는다. 근거가 있으면 「~한 연구 근거에 따라」로 출처를 붙이고, 없으면 효과를 언급하지 않는다.
- 이용자의 실제 이름·연락처·주민등록번호·검진 수치 같은 개인정보와 민감정보를 본문·댓글·첨부에 적지 않는다. 예시가 필요하면 가상의 값임을 명시한다.
- 외부 기관·협력사·법무 회신 내용은 회신 원문의 취지만 옮기고, 해석이나 추정을 덧붙이지 않는다. 계약 조항은 조 번호로만 가리킨다.
- 「법적 문제 없음」「승인 완료」처럼 법적 판단을 단정하는 문구는 법무 회신이 있을 때만, 회신 일자와 함께 쓴다.
- 제3자(경쟁사·특정 개인)에 대한 평가를 적지 않는다.

**좋은 예 / 나쁜 예**

| 나쁜 예 | 좋은 예 |
|---|---|
| 정훈샘 확인 대기 | 계산식 담당자의 확인을 기다린다 |
| 깃헙·사이트·쉐어포인트 전부 갱신 | GitHub 저장소, 공유 사이트, SharePoint 사본을 동일한 판으로 갱신한다 |
| 식후 걷기로 혈당 관리 | 식사 시각을 기준으로 식후 활동을 제안한다 |
| 법무 OK | 법무 회신(2026-10-13)에 따라 재동의 절차를 두지 않는다 |
| 대충 30일 정도 보관 | 보관 기간은 확정 전이며 30일을 제안한다 |

- 결정·변경은 본문을 고치지 말고 **댓글**에 날짜를 붙여 쌓는다. 본문은 「현재 기준」만 담는다.

- 완료 처리 전에 완료 조건 항목이 전부 체크됐는지 본다. 일부가 범위 밖으로 빠졌으면 「범위 밖」에 옮겨 적고 새 이슈 번호를 단다.
