# 생활탭 ‘이번 주 해석’ 화면 표시안

기준일: 2026-10-23 · 지표 가이드 V2 · 산식 I1 v0.25 · I2 v1.2 · I3 v8.24 검토안  
적용 화면: 생활탭 > 지표별 분석 > 이번 주 해석

## 1. 화면에서 이렇게 보입니다

### 해석 카드 기본 모양

```text
이번 주 해석                                      9.21–9.27
몸잠밥 지수
이번 주에는 수면이 알맞았던 날이 지난주보다 늘었어요.

수면 7~9시간인 날      5일       지난주 3일
8,000보 이상 걸은 날   4일       지난주 2일

식사 질문 답변이 적어 식사 균형은 이번 해석에 포함하지 않았어요.
```

화면 구성 순서는 **기간 → 지표명 → 쉬운 요약 문장 → 근거 숫자 → 보충 안내**다. 요약은 카드에서 가장 먼저 읽히도록 크게, 근거는 1~2개의 짧은 수치로, 제외 데이터 안내는 작은 보조 문장으로 표시한다. 데이터가 정상이고 전부 사용된 경우 보충 안내는 생략한다.

주간 기간은 제품에서 정한 한 가지 규칙(예: 월요일부터 일요일)을 일관되게 쓰며, 실제 날짜를 `9.21–9.27`처럼 표시한다. 진행 중인 주를 보여줄 때에는 끝나지 않은 요일을 지난주 전체와 직접 비교하지 않는다. 동일한 경과 일수끼리 비교하거나 주간 종료 후 확정 요약을 제공한다.

## 2. 상태별 완성 문구

아래 문구의 숫자는 예시다. 앱은 해당 지표 산출에 실제 사용된 값만 채운다. 비교 수치는 이번 주와 지난주가 같은 날짜 수, 단위, 출처 및 집계 규칙을 만족할 때에만 표시한다.

### A. 이번 주 변화가 늘어난 경우

```text
이번 주 해석                              9.21–9.27
몸잠밥 지수
이번 주에는 수면이 알맞았던 날이 지난주보다 늘었어요.

수면 7~9시간인 날      이번 주 5일       지난주 3일
8,000보 이상 걸은 날   이번 주 4일       지난주 2일

식사 질문 답변이 적어 식사 균형은 이번 해석에 포함하지 않았어요.
```

“좋아졌어요”, “더 건강해졌어요”라고 바꾸지 않는다. 실제 비교 항목이 ‘수면 7~9시간인 날’이면 그 이름 그대로 말한다.

### B. 지난주와 비슷한 경우

```text
이번 주 해석                              9.21–9.27
몸잠밥 지수
지난주와 비슷한 생활 흐름이 관찰됐어요.

수면 7~9시간인 날      이번 주 4일       지난주 4일
8,000보 이상 걸은 날   이번 주 3일       지난주 3일
```

제품이 정한 변화 기준 안에 든 경우에만 “비슷해요”라고 한다. 단순히 반올림 결과가 같다는 이유만으로 비슷하다고 판정하지 않는다.

### C. 비교 기준이 아직 없는 첫 주

```text
이번 주 기록                              9.21–9.27
몸잠밥 지수
이번 주 생활 기록이 모이고 있어요.

수면 7~9시간인 날      5일
8,000보 이상 걸은 날   4일

다음 주부터 이번 주 기록과 비교해 흐름을 알려드릴게요.
```

첫 주에는 증가/감소 화살표, “좋음/나쁨”, 지난주 대비 문구를 표시하지 않는다.

### D. 일부 데이터만 사용할 수 있는 경우

```text
이번 주 해석                              9.21–9.27
몸잠밥 지수
이번 주는 수면과 걸음 기록을 중심으로 살펴봤어요.

수면 7~9시간인 날      5일

식사 질문 답변이 충분하지 않아 수면과 걸음 기록만 반영했어요.
```

빠진 데이터는 사용자가 이해할 수 있는 항목 이름과 이유로 설명한다. 내부 상태명이나 오류 코드는 보여주지 않는다.

### E. 이번 주 기록이 아직 부족한 경우

```text
기록을 모으고 있어요                       9.21–9.27
몸잠밥 지수
이번 주 흐름을 보려면 기록이 조금 더 필요해요.

현재 기록된 날       2일
필요한 기록          지표 기준 충족 후 표시

평소처럼 기기를 착용하고 생활해 주세요. 기록이 쌓이면 이번 주 해석을 보여드릴게요.
```

최소 관찰 기준과 남은 일수를 정확히 계산할 수 있을 때만 “3일 더 필요해요”처럼 숫자를 쓴다. 기준값이 확정되지 않았거나 남은 일수를 계산할 수 없으면 “기록이 조금 더 필요해요”로 표시한다. 사용자를 탓하거나 특정 행동을 강요하는 표현은 쓰지 않는다.

### F. 아직 데이터가 하나도 없거나 동기화 중인 경우

**연동은 되어 있지만 동기화 중**

```text
기록을 불러오고 있어요
최근 건강 데이터를 가져오고 있어요. 완료되면 이번 주 흐름을 보여드릴게요.
```

**생활 데이터가 아직 없음**

```text
이번 주 기록이 아직 없어요
건강 데이터 연동을 확인하고, 기기를 평소처럼 사용해 주세요. 기록이 들어오면 이곳에서 이번 주 흐름을 확인할 수 있어요.
[데이터 연동 확인]
```

실제로 연동된 기기나 권한을 앱이 확인할 수 없다면 연동 문제라고 단정하지 않는다. 이 경우에는 “아직 표시할 생활 기록이 없어요”처럼 중립 문구를 쓴다.

### G. 지난주와 조건이 달라 비교할 수 없는 경우

```text
이번 주 기록                              9.21–9.27
몸잠밥 지수
이번 주 걸음 기록을 확인했어요.

8,000보 이상 걸은 날   4일

기록 기기가 달라 지난주와 직접 비교하지 않았어요. 같은 기준으로 기록이 쌓이면 변화도 함께 알려드릴게요.
```

기기 변경 사실을 확인하지 못했으면 “기록 기준이 달라” 등 원인을 추정하지 않고, “지난주와 비교할 수 있는 기록이 부족해 이번 주 기록만 보여드려요”라고 쓴다.

### H. 검증할 수 없는 기록이 포함된 경우

```text
기록을 확인하고 있어요
일부 기록을 확인할 수 없어 이번 주 해석에 반영하지 않았어요. 데이터를 다시 불러온 뒤 업데이트해 주세요.
[다시 불러오기]
```

복구 동작이 실제로 제공될 때만 버튼을 노출한다. 검증에 실패한 값을 해석 근거로 표시하지 않는다.

## 3. 지표별로 사용자가 보는 문장

### 몸잠밥 지수

**수면 · 식사 · 움직임 기록이 충분한 경우**

> 이번 주에는 수면 · 식사 · 움직임이 고르게 채워진 날이 많았어요.
> 수면 7~9시간인 날 5일 · 8,000보 이상 걸은 날 4일.

식사 자료가 없는 날은 몸잠밥 지수가 「일부 기록」이 되어 단계가 붙지 않는다. 이때 식사 내용을 추정하지 않고 “식사 기록이 적어 일부만 반영했어요”라고 안내한다.

### 내실천 지수

**행동 기회 판정이 확인된 경우**

> 이번 주에는 식후에 움직인 날이 많았어요.
> 식후에 움직인 때 9회 · 일어난 뒤 움직인 날 4일.

행동 이름과 횟수가 화면에 표시되어도 되는 서비스 항목일 때 구체적으로 쓴다. 기회 판정 없이 시간대별 걸음만 있는 주는 “틈틈이 움직인 시간”만 말하고 식후 행동을 했다고 쓰지 않는다.

> 이번 주 걸음 기록은 확인했어요. 식후 · 기상 후 행동 기록이 없어 틈틈이 움직인 정도만 반영했어요.

### 일상결 지수

**최근 28일 연속 기록이 있는 경우**

> 최근 4주 동안 걸음이 늘고 잠드는 시간이 일정해지는 흐름이에요.  
> 4주 전 하루 평균 6,000걸음 · 최근 주 7,500걸음.

이 지표는 지금 상태의 좋고 나쁨이 아니라 최근 4주 변화의 방향을 말한다. 4주 동안 비슷하면 활동이 많은 사람도 「유지기」로 표시한다.

## 4. 문구 선택 규칙

| 조건 | 제목/라벨 | 첫 문장 | 근거 표시 |
|---|---|---|---|
| 이번 주·지난주 모두 충분, 동일 기준, 증가 판정 | 이번 주 변화 | “[관측 항목]이 지난주보다 늘었어요.” | 이번 주 값 + 지난주 값 + 차이 |
| 이번 주·지난주 모두 충분, 동일 기준, 감소 판정 | 이번 주 변화 | “[관측 항목]이 지난주보다 줄었어요.” | 이번 주 값 + 지난주 값 + 차이 |
| 양 주 모두 충분, 변화 기준 이내 | 이번 주 흐름 | “지난주와 비슷한 흐름이 관찰됐어요.” | 양 주 값을 나란히 표시 |
| 이번 주 충분, 비교 기준 없음 | 이번 주 기록 | “이번 주 생활 기록이 모이고 있어요.” | 이번 주 값만 표시; 다음 주 비교 안내 |
| 필수 요소 중 일부만 충분 | 일부 기록으로 살펴봤어요 | “이번 주는 [사용 가능한 요소]를 중심으로 살펴봤어요.” | 사용한 요소 및 제외 이유 |
| 이번 주 최소 기준 미달 | 기록을 모으고 있어요 | “이번 주 흐름을 보려면 기록이 조금 더 필요해요.” | 현재 관찰량; 확정 기준이 있을 때만 남은 양 |
| 동기화 중 | 기록을 불러오고 있어요 | “최근 건강 데이터를 가져오고 있어요.” | 진행 상태가 실제 제공될 때만 |
| 비교 불가 | 이번 주 기록 | “이번 주 [관측 항목]은 확인했어요.” | 이번 주 값; 비교하지 않은 이유 |
| 검증 실패 | 기록 확인 중 | “일부 기록을 확인할 수 없어 이번 해석에 반영하지 않았어요.” | 안전한 재시도 안내 |

## 5. 화면 표시·접근성 규칙

- 증가/감소를 색상이나 화살표만으로 전달하지 말고 문장과 수치 라벨도 함께 표시한다.
- “좋아요/나빠요”, 초록/빨강만으로 건강 상태를 평가하지 않는다.
- 숫자는 단위와 기간을 함께 쓴다. 예: `이번 주 5일 · 지난주 3일`, `42,000걸음`.
- 0은 실제로 관측해 확인한 0일 때만 표시한다. 미수집/누락은 `0`으로 바꾸지 않고 ‘기록 없음’ 또는 ‘반영하지 않음’으로 안내한다.
- 비교가 가능한지 여부와 무엇을 근거로 삼았는지 사용자가 문장만 읽어도 이해할 수 있게 한다.
- 한 카드에 해석 문장 하나와 핵심 근거 최대 두 개를 우선 표시한다. 나머지 세부값은 ‘자세히 보기’에서 제공한다.
- 예시의 수치·날짜는 목업용이며, 실제 사용자에게는 계산 결과와 실제 집계 기간만 삽입한다.

## 6. 산출 측과 확정해야 할 연결값

화면은 아래 값을 산출 API에서 받아 표시한다. 화면이 별도 추정하거나 임계값을 새로 만들지 않는다.

```text
indicator_id, period_start, period_end,
status, summary_key, observed_values,
comparison_values, delta, unit,
used_components, excluded_components,
exclusion_reason, comparison_eligible,
observation_sufficiency, next_step
```

다음 제품 기준을 정해야 예시 문구의 조건을 실제 동작으로 연결할 수 있다.

1. 이번 주의 날짜 경계(예: 월~일)와 진행 중인 주 처리
2. 지표별 최소 관찰일과 필수 입력 구성
3. 증가/감소/비슷함을 나누는 변화 기준 및 반올림 규칙
4. 비교를 무효화하는 출처·기기·단위·집계 해상도 변경 조건
5. 수면 등 일부 요소가 제외됐을 때 우선 표시할 안내
6. 내실천 지수의 기회 판정 이벤트와 사용자에게 노출 가능한 행동명
7. 식이 질문 선택지별 점수표(몸잠밥 지수 식사 점수)

이 문서는 사용자에게 보이는 동작과 예시 문구를 구체화한다. 최소 기준과 변화 임계값은 승인된 지표 산식에서 받아야 하며, 예시값을 제품 규칙으로 간주하지 않는다.

## 7. 점수 3구간으로 ‘이번 주 해석’ 표시하기

이번 주 해석은 복잡한 증감 조건을 먼저 나누지 않고, **이번 주 지표 상태가 3구간 중 어디인지**로 결정한다. 내부 점수와 숫자 경계는 사용자에게 보여주지 않는다. 화면에는 지표별 상태 문구와 아래 한 문장만 표시한다.

### 간단한 조건

```text
상태가 높은 구간 → 긍정 문장
상태가 가운데 구간 → 중립 문장
상태가 낮은 구간 → 돌봄/확인 문장
단계를 붙일 수 없음(일부 기록 · 보조 추정만 · 준비 중) → 안내 문장
```

| 지표 | 높은 단계 | 가운데 단계 | 낮은 단계 | 단계 없음 |
|---|---|---|---|---|
| 몸잠밥 지수 | **이상적 하루** — “이번 주는 수면 · 움직임 · 식사가 권장에 가까운 날이 많았어요.” | **현실과 이상 사이** — “이번 주는 세 영역 중 비어 있는 날이 있었어요.” | **현실적 하루** — “이번 주는 수면 · 움직임 · 식사가 권장에서 먼 날이 많았어요.” | “기록이 더 쌓이면 이번 주 생활 흐름을 알려드릴게요.” |
| 내실천 지수 | **실천 고수** — “이번 주에는 기회가 올 때마다 자주 실천했어요.” | **실천 중수** — “이번 주에는 기회 중 일부에서 실천했어요.” | **실천 초보** — “이번 주에는 확인된 실천이 적었어요.” | “실천 기록이 더 쌓이면 이번 주 흐름을 알려드릴게요.” |
| 일상결 지수 | **탄력기** — “최근 4주 동안 생활이 오르는 흐름이에요.” | **유지기** — “최근 4주 동안 뚜렷한 변화 없이 이어졌어요.” | **주춤기** — “최근 4주 동안 생활이 내려가는 흐름이에요.” | “4주 기록이 모이면 보여드릴게요(준비 중).” |

### 카드에 보이는 형태

```text
이번 주 해석 · 9.21–9.27
몸잠밥 지수                              [이상적 하루]
이번 주는 수면 · 움직임 · 식사가 권장에 가까운 날이 많았어요.
```

상태 배지는 기존 지표별 문구를 그대로 쓰고, 설명은 한 문장만 붙인다. 홈·지표별 분석 어디에서도 점수, 100점 만점 값, 점수 경계 숫자는 노출하지 않는다.

### 꼭 지킬 제한

- 낮은 구간 문구는 그 지표가 실제로 측정한 내용을 설명한다. 질병, 건강 악화, 게으름, 실패로 해석하지 않는다.
- 내실천 지수는 행동 응답이 확인된 경우에만 “기회가 왔을 때 실천했어요”라고 한다. 응답 없이 걸음 보조 추정만 있는 주는 단계를 붙이지 않는다.
- 일상결 지수는 최근 4주 변화의 방향만 말한다. 주춤기도 “최근 4주 동안 내려가는 흐름”이라는 뜻이며 지금 생활이 나쁘다는 뜻이 아니다.
- 충분도 조건을 충족하지 못했거나 필수 근거가 누락되면 어떤 점수 구간 문장도 표시하지 않고 `관찰 중`을 쓴다.
- 한 주가 끝나기 전에 표시한다면 ‘이번 주’ 대신 ‘이번 주 현재까지’로 쓴다.

### 경계값 관련 구현 메모

세 지표 모두 0~100점으로 계산하고, 지표별 경계로 단계를 나눈다(§9, 표시 정책 v2). 일부 기록 · 보조 추정만 · 준비 중이면 단계를 붙이지 않는다.

## 8. 개발 구현용 표시 계약 (권장)

화면은 점수 숫자를 직접 해석하지 않는다. 지표 산출기가 `status`와 `state_band`를 반환하고, UI는 아래 매핑으로 배지와 한 문장을 렌더링한다.

### 필수 입력 필드

```json
{
  "indicator_id": "I1",
  "period_start": "2026-09-21",
  "period_end": "2026-09-27",
  "status": "available",
  "state_band": "high",
  "state_label": "이상적 하루",
  "observation_sufficiency": "sufficient",
  "evidence_keys": ["sleep", "movement", "diet"],
  "period_complete": true
}
```

`status` 값은 `available | observing | unavailable`로 통일한다. `state_band`는 `high | middle | low | null`이며, 산출기는 이 필드를 지표별로 판정한다. UI는 `raw_score`, `display_score`, 숫자 경계값으로 문구를 직접 분기하지 않는다. 숫자 경계값은 승인된 지표 설정에만 둔다.

### 우선순위가 있는 분기 조건

```text
1. period가 진행 중이면 제목에 “이번 주 현재까지”를 사용한다.
2. status != available 또는 observation_sufficiency != sufficient이면
   state_band와 관계없이 관찰 중 문구를 표시한다.
3. indicator_id == I2(내실천 지수)이고 행동 응답 없이 걸음 보조 추정만 있거나 모두 알 수 없으면
   단계 없이 안내 문구를 표시한다.
4. indicator_id == I3(일상결 지수)이고 28일 연속 기록이 확인되지 않았으면
   준비 중 문구를 표시한다.
5. 나머지는 state_band별 지표 문구를 표시한다.
```

### 지표×구간 문구 상수

| indicator_id | high | middle | low |
|---|---|---|---|
| I1 | `이상적 하루` / “이번 주는 수면 · 움직임 · 식사가 권장에 가까운 날이 많았어요.” | `현실과 이상 사이` / “이번 주는 세 영역 중 비어 있는 날이 있었어요.” | `현실적 하루` / “이번 주는 수면 · 움직임 · 식사가 권장에서 먼 날이 많았어요.” |
| I2 | `실천 고수` / “이번 주에는 기회가 올 때마다 자주 실천했어요.” | `실천 중수` / “이번 주에는 기회 중 일부에서 실천했어요.” | `실천 초보` / “이번 주에는 확인된 실천이 적었어요.” |
| I3 | `탄력기` / “최근 4주 동안 생활이 오르는 흐름이에요.” | `유지기` / “최근 4주 동안 뚜렷한 변화 없이 이어졌어요.” | `주춤기` / “최근 4주 동안 생활이 내려가는 흐름이에요.” |

### 비가용 문구 상수

| indicator_id | 조건 | label | message |
|---|---|---|---|
| I1 | 일부 기록 · 자료 부족 | 일부 기록 | “기록이 더 쌓이면 이번 주 생활 흐름을 알려드릴게요.” |
| I2 | 보조 추정만 · 확인 불가 | 확인 불가 | “실천 기록이 더 쌓이면 이번 주 흐름을 알려드릴게요.” |
| I3 | 28일 연속 기록 전 | 준비 중 | “4주 기록이 모이면 보여드릴게요.” |
| any | 동기화 중 | 불러오는 중 | “최근 건강 데이터를 가져오고 있어요.” |

### 의사코드

```typescript
function renderWeeklyInterpretation(x: WeeklyIndicator): ViewModel {
  const periodLabel = x.period_complete
    ? "이번 주 해석"
    : "이번 주 현재까지";

  if (x.status === "syncing") {
    return { periodLabel, label: "불러오는 중", message: "최근 건강 데이터를 가져오고 있어요." };
  }

  if (x.status !== "available" || x.observation_sufficiency !== "sufficient") {
    return observingCopy[x.indicator_id];
  }

  if (x.indicator_id === "I2" && !x.action_evidence_valid && !x.timed_steps_available) {
    return observingCopy.I2;
  }

  if (x.indicator_id === "I3" && x.coverage_days < 28) {
    return observingCopy.I3;
  }

  return copyByIndicatorAndBand[x.indicator_id][x.state_band];
}
```

실제 타입에서는 `syncing`을 `status` enum에 포함하거나 별도 `sync_state` 필드로 분리한다. 여기서는 분기 의미를 설명하기 위해 의사코드에 함께 적었다.

### 데이터 계약 및 미정 설정

- 산출기는 사용자 현지 주간 구간의 완료 여부를 반환한다. 미완료 기간 비교는 점수 산출 규칙이 명시적으로 동일 관찰 기간 비교를 지원할 때만 허용한다.
- `state_band` 판정 기준은 §9의 지표별 경계를 설정(`state_thresholds`)에 반영해 사용한다. 화면 코드에 기준을 중복 정의하지 않는다.
- 경계는 몸잠밥 50/80 · 내실천 25/75 · 일상결 Z ±0.05(반올림 전 변화값)다.
- `available`인데 `state_band=null`, 알 수 없는 지표 ID, 알 수 없는 band가 오면 안전하게 관찰 중으로 fallback하고 오류를 로깅한다.
- `evidence_keys`는 디버깅/설명 근거를 위한 기계 필드다. 사용자 문구를 UI에서 임의 합성하지 않는다.

### QA 수용 조건

| 입력 조건 | 기대 결과 |
|---|---|
| 충분한 관찰 + 승인된 high band | 지표별 high 배지와 high 문장 한 개 |
| 충분한 관찰 + 승인된 middle band | middle 배지와 middle 문장 한 개 |
| 충분한 관찰 + 승인된 low band | low 배지와 low 문장 한 개 |
| 관찰 부족, band가 우연히 채워져 있어도 | 해당 band 무시, 관찰 중 문구 |
| 내실천 지수: 보조 추정만 · 확인 불가 | 해당 band 무시, 단계 없는 안내 |
| 일상결 지수: 28일 연속 기록 전 | 해당 band 무시, 준비 중 문구 |
| 알려지지 않은 band/ID | 사용자에게 점수나 내부 오류를 보이지 않고 fallback |
| 주간 기간 미완료 | 기간 제목은 “이번 주 현재까지” |

위 계약의 API 필드와 fallback은 개발 전달용 제안이다. 지표 경계 숫자·충분도 판정·문구 의미의 최종 승인은 산출 명세에서 별도로 완료해야 한다.

## 9. 점수 경계 (표시 정책 v2)

이번 주 해석의 단계 판정은 지표 가이드 V2의 표시 정책을 따른다. 데이터 상태 검사가 항상 먼저다.

| 지표 | 낮은 단계 | 가운데 단계 | 높은 단계 |
|---|---|---|---|
| 몸잠밥 지수(I1) | 현실적 하루 `score < 50` | 현실과 이상 사이 `50 <= score < 80` | 이상적 하루 `score >= 80` |
| 내실천 지수(I2) | 실천 초보 `score < 25` | 실천 중수 `25 <= score < 75` | 실천 고수 `score >= 75` |
| 일상결 지수(I3) | 주춤기 `Z < -0.05` | 유지기 `-0.05 <= Z <= 0.05` | 탄력기 `Z > 0.05` |

경계값은 위쪽 단계에 포함한다(I1 · I2). 일상결은 반올림한 점수가 아니라 반올림 전 전체 변화값(Z)으로 판정한다 — 예: Z +0.05는 약 54.17점이어도 유지기.

```typescript
function getStateBand(id: "I1" | "I2" | "I3", score: number, z?: number) {
  if (id === "I1") return score < 50 ? "low" : score < 80 ? "middle" : "high";
  if (id === "I2") return score < 25 ? "low" : score < 75 ? "middle" : "high";
  return z! < -0.05 ? "low" : z! > 0.05 ? "high" : "middle";
}
```

최종 표시 순서:

```text
if I1이 일부 기록 · 자료 부족: 단계 없음
else if I2가 보조 추정만 · 확인 불가: 단계 없음
else if I3가 준비 중: 단계 없음
else: 위 경계로 단계 판정 → 지표별 이름과 한 문장 표시
```
