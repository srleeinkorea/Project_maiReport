01

한눈에 보기

이 문서가 다루는 것

고정 식사 질문(「{끼니}은 평소만큼 드셨나요?」)에 답하면 같은 카드에서 「{끼니}은 언제쯤 드셨어요?」를 이어 묻는 단계의 화면, 규칙, 데이터, 반영 위치.

가장 중요한 결정

질문 1개로 센다(식이 최대 3문항 · 전체 최대 5문항). 버튼은 1시간 간격이며 답한 시각에서 거꾸로 세고 끼니별 멈춤 시각에서 멈춘다. 어제 저녁과 「못 먹거나 거름」에는 묻지 않는다. 점수는 만들지 않는다.

아직 정해지지 않은 것

걸음 기록만으로 「식후에 움직였다」고 판정해도 되는지(계산식 전달 문서 확인 대기). 설계 · 데이터 계약 · 구현 기준은 모두 확정되어 반영되었다.

02

배경과 목표

자기돌봄 지표와 일상안정 지표에는 「식후에 움직였는지」를 보는 항목이 있으나, 앱이 식사 시각을 알지 못해 이 항목이 산출되지 않고 있다. 하루 8,000보 예시에서는 식후에 걸은 날과 걷지 않은 날이 모두 72점으로 표시된다.

식사 질문 바로 뒤에 시각을 한 번 더 받으면 이 항목이 채워진다. 같은 예시에서 식후에 걸은 날은 81점, 걷지 않은 날은 61점으로 나뉘어 실제 생활이 점수에 반영된다. 새 화면 없이 기존 질문 카드의 글과 버튼만 바꾸므로 사용자 부담은 버튼 1회로 제한된다.

Fig 1 · 문제 → 원인 → 이 기획
해석: 공란의 원인은 입력 경로의 부재이며, 추가 화면 없이 1문항을 이어 묻는 것으로 해소된다. 모의 데이터 기준 등급 오류일은 약 3분의 1로 줄어든다.
03

대상과 상황

인물상황바라는 것 · 실제 동작
지영 씨, 44세 사무직오후 1시 20분 점심을 먹고 앱을 연다. 「오늘 점심은 평소만큼 드셨나요?」에 「충분히 먹음」을 누른다길게 입력하지 않기를 바란다. 「오후 12:20 이후」 버튼 1회로 끝난다
민수 씨, 58세 자영업밤 11시 30분에 앱을 연다. 저녁은 7시 20분쯤 먹었다세밀한 질문을 원하지 않는다. 버튼은 「오후 8:00 이후 / 7:00~8:00 / 7:00 이전」이며 「7:00~8:00」을 고른다
아침 8시에 앱을 연 사용자이 시간대에는 「어제 저녁」을 묻는다어제 일을 시각까지 떠올리게 하지 않는다. 시각 단계가 나오지 않는다
04

범위

이번에 하는 것

  • 식사 질문 뒤 같은 자리에서 시각 단계 1문항(점심 · 저녁 「언제쯤」, 아침 「몇 시쯤」)
  • 버튼 3개 생성 규칙(1시간 간격 · 10분 내림 · 끼니별 멈춤 시각 · 아침 고정)
  • 답으로 식사 시각을 추정해 저장(건강 앱 → 걸음 단서 → 평소 시각 → 범위 가운데)
  • 「오늘 답변 모두 보기」에서의 답 수정
  • 데이터 계약 · 참조 구현 · 프로토타입 · 시뮬레이터 반영

하지 않는 것

  • 식후에 움직였는지 판정하는 지표 계산 자체(계산식 전달 문서 영역)
  • 식후 걷기 확인 알림
  • 시각 단계의 건너뛰기 버튼
  • 야식 질문(식사 시각 축, DIET-Q-04)의 변경
  • 식사 시각으로 좋음 · 나쁨 등급이나 코칭 문구를 만드는 일
05

동작 방식

오후 1시 20분에 앱을 열어 점심 질문에 답하는 경우다. 세 화면은 모두 홈의 같은 질문 카드이며 글과 버튼만 바뀐다.

Fig 2 · 화면 흐름 — 1/5 → 2/5 → 3/5
해석: 시각 단계는 새 화면이 아니라 같은 카드의 두 번째 상태다. 진행 번호에 1개로 들어가므로 사용자는 질문이 하나 늘어난 것으로 인지한다.
  1. 식사 질문에 답한다. 「충분히 먹음」 또는 「적게 · 몇 입만」이면 다음 단계로 간다. 「못 먹거나 거름」이면 먹은 시각이 없을 수 있으므로 시각 단계와 회전 질문 없이 다음 질문(2/3)으로 넘어간다.
  2. 같은 카드가 시각 질문으로 바뀐다. 점심 · 저녁은 「{끼니}은 언제쯤 드셨어요?」, 아침은 「아침은 몇 시쯤 드셨어요?」. 진행 번호는 1 늘어난다.
  3. 버튼 3개를 그 자리에서 만든다. 점심 · 저녁은 답한 시각을 10분 단위로 내린 뒤 1시간씩 거꾸로 센 구간이다. 오전 · 오후는 위에 작게, 시각은 크게, 아래에 「1시간 이내 · 1~2시간 전 · 그보다 전」을 작게 쓴다. 아침은 「7시 이전 / 7시~8시 / 8시 이후」로 고정한다.
  4. 버튼을 누르면 0.5초 뒤 다음 질문으로 넘어간다. 건너뛰기는 두지 않는다. 답과 함께 사용자가 본 버튼의 시각 구간을 저장한다.
  5. 서버가 식사 시각을 추정한다. 순서는 06의 Fig 4와 같다. 「모름」은 계산에서 제외될 뿐 점수를 깎지 않는다.
  6. 「오늘 답변 모두 보기」에는 식사 카드 아래에 시각 질문이 함께 보이며, 답할 때 본 버튼 그대로 다시 고를 수 있다.
Fig 3 · 점심 버튼이 답한 시각에 따라 바뀌는 방식 — 받침 12시, 멈춤 오후 2시
해석: 버튼은 항상 답한 시각보다 앞선 구간만 보여 준다. 12시 전으로 내려가지 않게 받치고 오후 2시가 지나면 정각에서 멈추어, 늦게 답해도 버튼이 점심 시간대 안에 머문다. 저녁은 받침 17시 · 멈춤 21시로 같은 방식이다.
06

규칙과 예외

규칙예시예외 · 비고
시각 단계는 식사 답이 「충분히 먹음」「적게 · 몇 입만」이고 끼니가 오늘 아침 · 점심 · 저녁일 때만 나온다오후 2시 10분 점심 「적게 · 몇 입만」 → 시각 단계 노출「못 먹거나 거름」 · 어제 저녁(자정~오전 10시) · 건강 앱에 그 끼니 식사 기록이 있으면 묻지 않고 조건상 생략으로 기록한다
질문 1개로 센다. 진행 번호도 따로 센다식사 1/5 → 시각 2/5 → 채소 3/5시각을 묻지 않는 날은 1/4부터. 「못 먹거나 거름」이면 시각 · 회전이 빠져 다음이 2/3
점심 · 저녁 버튼은 답한 시각을 10분 단위로 내린 뒤 1시간씩 거꾸로 센 3구간이다오후 1:47 → 1:40 기준 → 12:40 이후 / 11:40~12:40 / 11:40 이전반올림하지 않는다. 반올림하면 아직 오지 않은 시각이 버튼에 들어간다
끼니별 멈춤 시각(점심 오후 2시 · 저녁 오후 9시)을 넘으면 그 시각에서 멈춘다오후 4:30 점심 → 오후 1:00 이후 / 12:00~1:00 / 12:00 이전멈춘 동안은 아래 작은 글씨를 뺀다
질문 시작 시각(점심 12시 · 저녁 5시) 아래로는 내려가지 않는다오후 12:20 점심 → 오후 12:00 이후부터저녁 5시대는 「오후 5:00 이후 / 4:00~5:00 / 4:00 이전」으로 받치고, 2 · 3번 답은 구간이 비어 「모름」으로 처리한다

시각 표기는 「오후 1:10」처럼 오전 · 오후를 붙인다앞뒤가 다르면 「오전~오후 11:20~12:20」아침 버튼은 「7시 이전」처럼 시만 쓴다. 시각 단계 버튼은 답 버튼 5~7자 규칙의 예외다
점수 · 등급 · 축 상태를 만들지 않는다어느 버튼을 눌러도 식이 축 판정과 목표 선정은 그대로다식사 시각 응답은 사실 빈도만 저장한다는 기존 원칙을 따른다
시각 단계 도중 앱을 나갔다 오면 식사 답은 두고 버튼은 다시 들어온 시각으로 새로 만든다1:20 식사 답 → 이탈 → 3시 복귀 → 멈춘 버튼(1:00 이후 / …)—
점심에는 「드신 뒤 답해주세요」 안내를 붙이지 않는다먹기 전에 답할 수 있는 시간은 오후 12:00~12:30뿐이다이 시간대 답이 10%를 넘으면 붙인다
Fig 4 · 추정 시각을 정하는 순서 — 세 끼 공통
해석: 위에서부터 먼저 맞는 규칙을 쓴다. 확신이 높은 근거(건강 앱 · 걸음 단서)가 없을 때만 평소 시각이나 범위 가운데로 내려가며, 범위가 너무 넓으면 추정하지 않는다.

08

기대 효과와 성공 기준

실제 사용 데이터가 없어 가상 사용자로 끼니마다 2만 일을 생성해 계산하였다(가정은 근거 항목 참조). 수치는 모의 결과이며 내부 목표치와 함께 적는다.

Fig 5 · 식사 시각 오차 — 30분 이내 적중 비율과 내부 목표 85%
