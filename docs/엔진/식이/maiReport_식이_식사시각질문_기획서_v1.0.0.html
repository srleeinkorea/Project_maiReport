한눈에 보기

이 문서가 다루는 것

  • 식사 질문에 답한 뒤, 같은 카드에서 한 번 더 묻는 질문
    「{끼니}은 언제쯤 드셨어요?」
  • 한 장 요약과 설계 정리를 통합한 정책·규칙·데이터 기준
    화면 문구·끼니별 예시·조작 화면은 연결된 화면설계서에서 확인

가장 중요한 결정

  • 질문 1개로 셈
    식이 최대 3문항, 전체 최대 5~6문항
  • 선택지는 3개
    점심 · 저녁은 「1시간 이내 / 1~2시간 전 / 그보다 전」
    답한 시각에서 1시간씩 거슬러 올라간 구간이 각 선택지에 숨어 있음(화면에는 글자만 보임)
    예) 오후 1:20에 답함
    「1시간 이내」 = 낮 12:20~1:20
    「1~2시간 전」 = 오전 11:20~낮 12:20
    「그보다 전」 = 오전 11:20 전(점심은 11시부터로 봄)
    아침은 「7시 이전 / 7시~8시 / 8시 이후」, 저녁을 밤 9시 뒤에 답할 때와 어제 저녁은 「7시 이전 / 7시~9시 / 9시 이후」로 고정
  • 늦게 답해도 고를 칸이 있게
    점심은 오후 2시가 지나서 답해도 2시에 답한 것과 같은 선택지를 보여 줌
    예) 오후 4:30 점심 → 「1시 이후 / 12시~1시 사이 / 12시 이전」
    저녁은 밤 9시가 지나서 답하면 「7시 이전 / 7시~9시 / 9시 이후」로 바꿔 물음
    예) 밤 11:30 저녁 → 5시에 먹은 사람도 10시에 먹은 사람도 고를 수 있음
  • 묻지 않는 경우
    「못 먹거나 거름」을 골랐을 때
  • 어제 저녁도 물음
    선택지는 「7시 이전 / 7시~9시 / 9시 이후」 고정 (「9시 이후」는 9시에 먹은 것으로 봄)
    생활 변화 추이가 최근 7일의 식후 행동을 합산해 어제 값도 쓰이기 때문
  • 평가하지 않음
    언제 먹었는지를 잘했다 · 못했다로 매기지 않음
    어떤 선택지를 골라도 식이 점수 · 오늘의 목표는 그대로
    답은 「밥 먹고 움직였는지」를 보는 데만 씀

적용 전 확인할 것

  • 다음 버전 적용 일정, 건강 앱 식사 기록의 동의 범위, 서버 구현·검증은 별도 확인
  • 임시값(5분 · 300보 · 끼니 시작 · 끝 기본값 등)은 출시 뒤 실제 데이터로 고침

범위

이번에 하는 것

  • 식사 질문 뒤 같은 자리에서 시각 단계 1문항(점심 · 저녁 「언제쯤」, 아침 「몇 시쯤」)
  • 선택지 3개 만드는 규칙: 글자는 「1시간 이내 / 1~2시간 전 / 그보다 전」. 각 선택지의 시각 구간은 답한 시각을 10분 단위로 내린 뒤 1시간씩 거꾸로 센 구간 3개(화면에는 보이지 않고 저장에만 씀). 점심은 오후 2시가 지나서 답해도 2시에 답한 것과 같은 선택지(선택지 상한 시각), 점심 12시 · 저녁 4시 아래로는 내려가지 않음(선택지 하한 시각). 상한 · 하한에 걸린 동안은 시각 글자로 보여 줌.
    아침은 「7시 이전 / 7시~8시 / 8시 이후」, 저녁을 밤 9시 뒤에 답할 때와 어제 저녁은 「7시 이전 / 7시~9시 / 9시 이후」 고정
  • 답으로 식사 시각 추정 · 저장(건강 앱 기록 → 선택지 범위의 가운데)
  • 식후에 걸었는지 걸음 기록으로 판정해 완료 · 미완료 · 모름으로 저장
  • 「오늘 답변 모두 보기」에서 답 수정

하지 않는 것

  • 사용자에게 식사 시각을 숫자로 직접 입력하게 하는 것
  • 식사 시각으로 좋음 · 나쁨 등급이나 코칭 문구를 만드는 것
  • 판정 결과로 점수를 내는 지표 계산(계산식 전달 문서 영역)

늦게 답할수록 선택지가 점심 시간대 밖으로 밀려남.
그래서 2시가 지나면 2시에 답한 것과 같은 「1시 이후 / 12시~1시 사이 / 12시 이전」을 보여 줌. 「1시 이후」는 점심을 늦어도 2시에 먹는다고 보아 1:30으로 잡음.
점심은 12~2시에 몰려 있어 이 세 칸으로 거의 다 덮이므로, 저녁처럼 2시간 칸 고정 선택지로 바꾸지 않음.
이때는 「1시간 이내」가 사실과 달라 시각 글자를 그대로 보여 줌.

걸음 기록으로 판정함

판정 방법
식후 걸음 보는 시간 안에 5분 넘게 이어 걸었거나(분당 20보 이상), 합계 300보 이상이거나, 운동 기록이 시작됐으면 「걸었음」. 아니면 「안 걸었음」. 걸음 기록이 비어 있는 시간이면 「모름」.
예시
오후 12:20~1:50 사이에 10분 걸음 → 걸었음. 행동 기회 대응 식후 칸 +8.3점.
같은 날 걷지 않았다면 → 안 걸었음. 0점(감점 없음).
화면
더 바뀌는 것 없음.
지표
시각을 받은 날마다 식후 칸이 채워짐. 생활 변화 추이의 식후 비율 비교는 답이 2주 쌓인 뒤부터 들어감.
남는 일
판정 로직 개발(참조 구현 있음). 5분 · 300보는 임시값, 출시 뒤 조정.

답 B

안 됨. 사용자 확인이 있어야 함

판정 방법
사용자가 식후 걷기 목표를 완료로 누른 날만 「걸었음」. 확인 알림은 보내지 않음.
확인이 없으면 걸음이 없어도 「안 걸었음」을 만들 수 없어 「모름」.
예시
식후 걷기 목표를 완료로 누름 → 걸었음. +8.3점.
누르지 않음 → 모름. 0점.
화면
더 바뀌는 것 없음.
이미 있는 목표 완료 표시를 씀.
지표
식후 걷기 목표가 나오고 사용자가 완료를 누른 날만 채워짐. 점수가 깎이는 일은 거의 없지만 올라가는 날도 적음.
남는 일
식후 걷기 목표와 식사 시각을 묶는 규칙.

답 C

시각이 확실할 때만 걸음으로 판정함

판정 방법
건강 앱 식사 기록이 있는 날만 A처럼 판정함.
선택지 범위의 가운데로 잡은 날은 「모름」으로 두어 계산에서 뺌.
예시
건강 앱에 오후 12:25 식사 기록이 있으면 오후 12:25~12:55를 보고 판정함.
단서 없이 범위 가운데로 잡은 날 → 모름. 계산에서 제외.
화면
더 바뀌는 것 없음.
지표
A보다 채워지는 날이 적지만, 시각이 틀려서 잘못 판정할 일도 적음.
남는 일
A와 같고, 확신 정도를 판정 조건으로 넘기는 것만 더해짐.
