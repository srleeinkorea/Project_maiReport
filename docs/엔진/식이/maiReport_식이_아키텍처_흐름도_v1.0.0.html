식이 아키텍처

고정 1문항 + 회전 최대 1문항 · 문항별 3개 선택지 · 회전은 식습관 관찰 · 달성은 완료 토글

질문 선정과 응답 처리

  1. 세션 날짜는 사용자 시간대 04시 경계, 끼니 날짜는 실제 달력일로 기록함.
    지난 끼니는 진입 시각으로 판정하며 경계는 10 · 12 · 17시다. 17~24시에는 오늘 저녁을 묻고 식사 후 답하도록 안내하며, 00~04시에는 어제 저녁을 물음.
  2. 이미 처리한 문항은 다시 내지 않음. 미응답 문항만 재진입 시 지난 끼니를 갱신함.
  3. 회전 후보는 실제로 물을 수 있고 질환별 금지와 충돌하지 않는 축임.
    야식 횟수를 묻는 식사 시각 문항은 04~10시 진입에서만 가능함.
    00~04시는 지난 끼니가 어제 저녁이어도 이 문항을 내지 않음.
  4. 연속 3일 같은 축 제외 후 후보가 비면 이 반복 제외만 해제함.
  5. 최근 28일 유효 답이 적은 축 → 사용자 확인 질환·검진 연결 축 → 마지막으로 물은 날이 오래된 축 → 표 순서로 선택함.
    질환 연결은 동률 우선이며 타 축을 영구 제외하지 않음.
  6. 답변이 없으면 문항은 미완료(PENDING)로 남고 집계에서 제외함.
    회전 후보 자체가 없으면 조건상 생략으로 기록함.
  7. 그날 나온 질문을 모두 처리한 시점에 잠긴 목표 3개를 한 번에 생성함.
    식이 문항만 끝나도 식이 타일이 먼저 열리지는 않음.
    조건상 생략도 처리 완료에 포함함.

문항은 한 끼의 제한된 사실을 물음. ‘충분히 먹음’은 적정 영양량이 아니며, 국물 섭취로 하루 나트륨을, 반찬 수로 총중량을, 식후 포만감으로 식사 속도를 계산하지 않음.
식사 시각 응답은 사실 빈도만 저장하고 좋음·나쁨 등급을 만들지 않음.

목표 생성

  1. 질환별 금지를 먼저 확인함.
    금지는 질환규칙 시트 한 곳에서만 보고 문구마다 제한을 따로 달지 않음 — 앱이 개인 처방식이나 식품 알레르기를 받는 경로가 없어 지킬 수 없는 조건이었음.
    고위험 질환도 목표 생성을 통째로 멈추지는 않음 — 질환규칙의 금지 성격에 해당하는 문구만 빼고 나머지에서 고름. 그렇게 뺐는데 남는 후보가 하나도 없을 때만 개별 식사 계획 확인 안내로 끝남.
  2. 현재 고정 답이 적게 먹음 또는 못 먹거나 거름이면 회복 후보, 그 외 사용자 확인 질환 → 검진 참고 신호 → 피로/수면 부담 → 일반 후보 순서로 고름. 이 순서보다 안전 필터가 우선함.
  3. 회복 목표는 물·단백질 한 가지로 충분한 회복을 보장하지 않음.
    반복 섭취 부족·치료 중·연하 문제는 일반 회복 목표로 덮지 않음.
  4. 운영 목록의 143개 문구 중 과일 추천 문구를 제외하고, 질환별 금지와 실행 가능한 시간·상황을 검사함.
    식사 전체·매 끼니 목표는 이미 일부 끼니가 지난 뒤 소급 완료를 요구하지 않음.
  5. 후보가 없으면 아래 단계나 다른 허용 축을 찾되 동일한 필터를 다시 적용함.
    그래도 없으면 ‘오늘은 개인 식사 계획을 먼저 확인해 주세요’ 안내 상태로 저장함.
    완료율·연속 미완료·단계 계산에서 제외함.
  6. 문구 ID·버전·행동·이유를 생성 시점의 값으로 저장함.
    저녁 식사를 마친 뒤 또는 00~04시에는 자동으로 공복·야식 제한 목표를 만들지 않음.
  7. 고정 답 수정 시 아직 완료하지 않은 목표만 재선정함.
    완료 기록은 그대로 보존함.
    새 위험 정보는 당일에도 안전성 재검사를 수행하고 현재 행동을 중지할 수 있지만 과거 기록을 덮어쓰지 않음.

식사 시각 문항으로 임상적 야식 위험을 판정하지 않으며, 곡류·식이섬유 19문구를 포함한 불필요한 보류 문구 62개는 운영 목록에서 삭제했음.
운영 문구는 143개이며 삭제 이력은 별도 근거대조 파일에만 보존함.
