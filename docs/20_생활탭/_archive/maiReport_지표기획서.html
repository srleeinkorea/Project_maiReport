01 · Principles

공통 원칙

세 지표는 임상 판정도, 하루를 평가·줄세우는 점수도 아닙니다. 사용자가 자기 생활 흐름을 이해하고 조절 가능한 지점을 알아차리도록 돕는 해석 지표입니다. 아래 원칙이 구성·문구·화면 판단에 우선합니다.

P1

질문은 보조 정보

질문 응답은 지표를 직접 올리거나 내리는 입력이 아닙니다. 이유 설명·맥락·신뢰도 보강에만 씁니다. 질문이 없어도 지표는 가능한 범위에서 표시되며, 질문을 안 했다는 이유로 낮은 상태를 주지 않습니다.

P2

디바이스 데이터가 기본 축

수집 가능한 디바이스 데이터가 계산의 기본 축입니다. watch를 쓰지 않는 사용자를 불리하게 하지 않습니다. watch가 있으면 더 자세히, 없으면 낮은 해상도로 해석합니다.

P3

기록은 점수 보너스가 아님

식사 기록처럼 사용자가 남긴 기록은 ‘기록했다는 사실’ 자체로 상태를 올리지 않습니다. 기록이 있으면 특정 생활 순간을 더 잘 알아볼 뿐입니다. 식사 기록만 있으면 ‘기준점 확인됨’ 수준입니다.

P4

숫자는 내부 계산용

내부적으로 계산 값을 가질 수 있지만, 정밀 숫자를 그대로 보여주는 방식은 기본 방향이 아닙니다. 사용자에게는 “충분함 · 빠듯함 · 관찰 중 · 일부 연결됨”처럼 이해 가능한 상태 표현을 우선합니다.

P5

종합 점수 없음

세 지표를 합산하거나 평균 내어 하나의 점수로 만들지 않습니다. 각 지표가 답하는 질문이 다르기 때문입니다. 나란히 보면서 현재 생활의 관계를 이해합니다.

P6

rule-based · 후속 보정

학습 환경이 없어 초기 버전은 미리 정한 규칙과 안전장치로 동작합니다. 실사용 데이터는 지표가 이상하게 반응하는지 확인하고 보정하는 데만 사용합니다.

지표가 답하는 질문

생활여유 — 지금 내 하루를 이어갈 여유가 충분한가.  ·  자기돌봄 — 내가 조절 가능한 행동들이 실제 하루 안에서 얼마나 이루어졌는가.  ·  일상안정 — 최근 내 생활 신호가 나에게 맞는 방향으로 바뀌고 있는가.

02 · Pipeline

공통 해석 파이프라인

세 지표 모두 같은 처리 흐름을 거칩니다. 지표별 차이는 구성 요소 구성과 방향(무엇이 좋은 쪽인가), 규칙뿐입니다. 아래 05·06 단계의 계수와 경계값은 미확정입니다.

01 · SIGNAL원천 수집

HealthKit / Health Connect 디바이스 데이터가 기본 축. 질문·기록은 보조

02 · QUALITY품질·해상도 판정

최신성·연속성·이상치 제거. watch 유무로 해석 해상도 결정

03 · BASELINE개인 기준선

최근 기간 개인 데이터의 범위·중심. 윈도우 길이 미확정

04 · COMPONENT구성 요소 평가

지표별 구성 요소를 규칙으로 평가. 핵심/보조 역할 구분

05 · INTERNAL내부 값

구성 요소를 합쳐 내부 계산 값 산출. 계수 미확정 · 사용자 비노출

06 · STATE상태 판정

내부 값 → 상태 표현(충분함·일부 연결됨 등) + 방향(개선·유지·주의)

07 · EXPLAIN이유·행동

가장 크게 기여한 구성 요소로 이유 설명, 코칭 1행동 연결

미확정

재계산 주기, 주간 스냅샷 저장 시점, 내부 값 → 상태 경계, 개인 기준선 윈도우는 아직 정하지 않았습니다. ‘오늘의 컨디션’은 당일 해석, ‘지표별 분석’은 주간 시계열이라는 방향만 유지합니다. (9장)

참고 · 현행 엔진 v5.7 산식 테스트용 고정 계수 · 확정값 아님

“지금 내 하루를 이어갈 여유가 충분한가?”
핵심 관점
부담(한쪽으로 몰림: 오래 안 움직임 · 활동이 늦은 시간에 몰림 · 회복할 틈 없이 하루가 이어짐) ↔ 여유(작은 여백: 짧게라도 분산된 움직임 · 무리한 흐름을 낮추는 시간 · 한 방향으로 과하게 밀리지 않음)
구성 요소
비활동 압력(여력 낮추는 핵심) · 늦은 시간/몰린 활동(부담 키우는 보조) · 분산된 가벼운 움직임(여력 높이는 핵심) · 쉬는 방향의 맥락(잠·휴식·낮은 자극, 해석 보강) · 주관 답변·watch 생체 신호(HRV·안정 시 심박, 직접 점수화 안 함, 신뢰도·맥락 보강)
최소 표시 조건
걸음 수 또는 활동 시간대 데이터 1개 + 개인 기준선(윈도우 미확정). watch 없으면 저해상도로 표시, 질문 없어도 표시. 기준선 부족 시 ‘관찰 중’.
산출(v0.1, 규칙 기반)
구성 요소를 개인 기준선 대비 규칙으로 평가 → 비활동 압력·몰림은 여력을 낮추고, 분산된 움직임·쉬는 맥락은 높이는 방향으로 내부 값 결합. 가중치·경계값은 미확정(9장).
방향 표기
최근 해석 대비: 개선 ▲좋아졌어요 / 유지 · / 주의 ▼주의가 필요해요 (임계 미확정)
빠듯부담이 여유보다 큼 · 회복 틈이 적음
보통부담과 여유가 평소 범위
충분여유가 유지됨 · 흐름이 분산

‘관찰 중’ = 데이터가 모이는 중. 사용자에게는 위 상태 표현만 노출하며, 내부 계산 값의 경계는 미확정.  예시 문구 — “걸음 수는 평소만큼이지만 활동이 저녁에 몰렸고 중간에 쉬는 흐름이 적었어요. 오늘은 여유가 빠듯한 편이에요. (참고 정보)”

말하지 않는 것 — 피로도 · 수면 점수 · 스트레스 점수 · 회복 점수 · readiness 점수 · 치료 효과나 건강 상태 판단.

05 · Metric 2

자기돌봄 (Self-Care Moments)

자기돌봄

잘 챙김 ↔ 뜸함 · 기준점–행동 연결
정의
스스로 조절할 수 있었던 순간(기준점: 식사 후 · 긴 비활동 뒤 등)에 실제로 몸을 움직여 챙겼는지를 보는 해석 지표. 많이 움직였는지가 아니라 ‘행동할 수 있는 순간’과 ‘그 근처에서 실제로 일어난 짧은 움직임’의 연결을 본다. 이름은 넓지만 지표가 보는 것은 이 연결로 한정된다.
사용자 질문
“내가 조절 가능한 행동들이 실제 하루 안에서 얼마나 이루어졌는가?”
이름 감수 기준
사용자의 주체성을 긍정적으로 표현할 것. ‘의지력 · 순응도 · 실천 점수 · 목표 달성률’처럼 평가·압박하는 어투는 배제(문구에도 동일 적용).
해당 예
식사 후 짧게 걷기, 긴 비활동 뒤 가볍게 움직이기, 하루 중 조절 가능한 시간대에 몸 풀기
구성 요소
조절 가능한 기준점(식사·긴 비활동·일정 전후, 연결을 보는 출발점) · 기준점 근처의 실제 행동(지표를 움직이는 핵심) · 행동의 배치(해석 보강) · 반복되는 연결(하루 해석 안정성) · 기록 유무(평가 가능성·이유 설명 보강) · 질문 응답(직접 점수화 안 함, 맥락 보강)
기록만 있는 경우
식사 기록만 있고 실제 움직임 데이터가 없으면 “식사라는 기준점은 확인됨” 수준. 기록 행위에 대한 낮은 인정이지 점수 보너스가 아니며, 좋은 상태로 올리지 않는다.
질문 대체
일반 자가보고(어려움 응답 평점)로는 대체 불가 — 어려움 응답은 이 지표에 반영되지 않는다. “식사 시각 + 식후에 움직였는지”를 구조화해 묻는 보고 경로는 산출 가능하나 저해상도·별도 눈금이고, 자가보고를 실제 연결로 인정할지는 미확정(9장 B-3). 식사 시각이 없으면 긴 비활동 종료 시점을 기준점으로 쓴다.
최소 표시 조건
기준점을 인식할 신호(식사 기록 또는 긴 비활동 등) 1개 + 활동 데이터. 기준점 신호가 전혀 없으면 ‘관찰 중’.
산출(v0.1, 규칙 기반)
기준점을 식별하고, 각 기준점 근처 창에서 실제 행동 유무를 판정 → 연결된 비율과 반복성으로 내부 값. 창 길이·경계값 미확정.
방향 표기
전일 대비: 개선 ▲연결이 늘었어요 / 유지 · / 주의 ▼연결이 줄었어요
뜸함기준점은 있었지만 대부분 이어지지 않음(거의 연결 안 됨)
조금 챙김평소만큼 이어짐(일부 연결됨)
잘 챙김대부분의 기준점에 짧은 행동이 붙음(잘 연결됨)

예시 문구 — “점심 기록 뒤 30분 안에 짧게 걸었고, 저녁 뒤에는 앉아 있었어요. 오늘은 조절 가능한 순간 중 일부에서 몸을 챙겼습니다. (참고 정보)”

말하지 않는 것 — 의지력 평가 · 코칭 순응도 · 목표 달성률 · 활동량 점수. 하루 총 걸음 수가 많아도 기준점과 연결되지 않으면 좋은 상태로 단정하지 않고, 활동량이 크지 않아도 적절한 순간에 행동이 붙으면 의미 있는 연결로 본다.

06 · Metric 3

일상안정 (Life Steadying)

일상안정

안정 쪽 ↔ 쏠림 쪽 · 주 단위 · 양방향
정의
최근 며칠의 생활 신호가 개인의 평소 범위에서 어느 방향으로 가고 있는지를 보는 해석 지표. 정해진 목표 달성이 아니라 개인 기준 대비 변화 방향. 이름은 ‘안정’이지만 값은 양방향이다 — 제자리를 찾아가는 흐름일 수도, 한쪽으로 쏠리는 흐름일 수도 있다.
사용자 질문
“최근 내 생활 신호가 나에게 맞는 방향으로 바뀌고 있는가?”
핵심 관점
개인 평소 범위 안에서 안정되는지 · 반복되던 막힘(늦은 활동 · 긴 비활동 · 흐름 끊김)이 줄어드는지 · 반대 방향 신호가 커지는지
구성 요소
개인 기준 범위(변화 판단 기준) · 최근 벗어남(변화 방향 핵심) · 반복되는 막힘의 완화(긍정 방향 보강) · 반대 신호와 흔들림(과도한 해석 방지) · 지식 기반 맥락(일반적으로 더 나은 방향으로 볼 수 있는 패턴, 보조 해석)
최소 표시 조건
여러 날의 반복 패턴이 필요. 관측 기간 미확정(다른 두 지표보다 김). 미달 시 ‘관찰 중’.
산출(v0.1, 규칙 기반)
최근 구간과 그 직전 구간을 개인 기준선 대비 비교 → 반복성 확인 후 방향 판정. 하루 등락은 반영하지 않음. 구간 길이·임계 미확정.
방향 표기
주 단위로만 갱신. 전주 대비 개선 ▲ / 유지 · / 주의 ▼. 일 단위 화살표는 표시하지 않음.
쏠림 쪽늦은 활동·불규칙이 반복적으로 늘고 있음(한쪽으로 쏠리는 중)
그대로큰 흐름 변화 없음(뚜렷한 방향 없음)
안정 쪽늦은 활동·불규칙이 반복적으로 줄고 있음(제자리를 찾아가는 중)

예시 문구 — “지난 2주간 늦어지던 저녁 활동이 최근 며칠 이른 시간으로 돌아왔어요. 일상이 제자리를 찾아가는 흐름이에요. (참고 정보)”

말하지 않는 것 — 오늘의 몸 상태 · 오늘의 활동량 점수 · 목표 달성률 · 치료 효과. 하루만 좋아진 것은 긍정 변화로 단정하지 않으며, 반복되는 방향성이 확인되어야 한다.

07 · State & Copy

상태 표현 규칙

사용자에게는 숫자가 아니라 상태 표현을 보여줍니다(P4). 화면(오늘의 컨디션 · 지표별 분석)은 이 규칙만 참조합니다.

공통 상태 표현

지표낮은 쪽중간좋은 쪽데이터 부족
생활여유빠듯보통충분관찰 중
자기돌봄뜸함조금 챙김잘 챙김관찰 중
일상안정쏠림 쪽그대로안정 쪽관찰 중

칩·요약에는 위 2~4자 명사형을 쓰고, 말풍선에는 “충분해요 · 보통이에요 · 빠듯해요”처럼 ~요 문장형으로 일괄 변환합니다. 괄호 안 회의록 원문 어휘(일부 연결됨 등)는 설명 문구에 유지합니다. 일상안정의 ‘안정’은 좋은 쪽 결과값에만 두고, 나쁜 쪽은 ‘흔들림’이 아니라 ‘쏠림’(방향)으로 씁니다.

방향(변화) 표기

▲ 개선

좋은 방향으로 반복 확인된 이동. 좋은 방향은 지표마다 다름(위 표 ‘좋은 쪽’).

· 유지

뚜렷한 변화 없음. “큰 변화 없이 유지”. 임계 미확정.

▼ 주의

나쁜 방향으로 이동. 단정 대신 “주의가 필요해요” 수준.

문구 생성 규칙

COPY RULE

① 문구 = [상태 서술] + [가장 크게 기여한 구성 요소 1~2개]. 예: “활동이 저녁에 몰려 여유가 빠듯한 편이에요”.
② 항상 ‘평소(개인 기준) 대비’ 상대 표현. 절대 수치의 정상/비정상 판정 금지.
③ 데이터가 부족하면 “관찰 중 · 일부 데이터로 본 참고” 명시.
④ 질문·기록이 지표를 올린 것처럼 쓰지 않는다(P1·P3).
⑤ 의료 우려 키워드(통증·이상 증상 등 자가보고) 감지 시 문구 대신 상담 안내로 전환.

배제 표현

“정상 / 비정상 / 위험 / 질환 위험 / 진단 / ~해야 합니다(치료·복약 지시)”, 그리고 평가·압박 어투(“의지력 / 순응도 / 실천 점수 / 목표 달성률”). → MRS 9장 표현 가이드와 동일 기준.

08 · Data Resolution

데이터 해상도와 결측 처리

watch 유무 · 질문 유무 · 기록 유무에 따라 해상도가 달라지지만, 어느 경우에도 지표는 가능한 범위에서 표시됩니다(P1·P2). 화면의 상태값(정상·부분수집·미수집)과 연결됩니다.

조건해상도표시화면 상태값
watch + 충분한 기준선높음상태 표현 + 방향 + 이유 + 근거 구성 요소정상
폰 활동 데이터만낮음상태 표현(개략) + 이유 축약, 방향 생략 가능부분수집
기준선/기준점 부족—상태 미표시, “관찰 중 · 데이터가 모이면 보여드려요”미수집

결측·저품질 처리

  • 최신성 초과 입력은 제외하고 남은 데이터로 재해석
  • 이상치(생리적 범위 밖)는 윈저라이즈 후 사용, 로그 기록
  • watch 미착용일은 해당 지표를 저해상도로
  • 기기 연동 해제: 세 지표 모두 ‘관찰 중’, 재연결 유도

질문·기록·과거 구간

  • 질문·기록이 없어도 지표는 표시. 있으면 이유·신뢰도만 보강, 상태는 안 올림
  • 지난 주는 그 주 스냅샷 기준 요약(스냅샷 시점 미확정)
  • 지표 정의·경계 변경 시 과거 스냅샷은 재계산하지 않음(버전 태그)
해상도란

화질이 아니라 “엔진이 하루를 얼마나 세밀하게 볼 수 있느냐”입니다. 고해상도 = 시간대별 활동·심박·수면이 있어 하루의 배치(움직임 분산·공백·부하)를 재구성할 수 있는 상태. 저해상도 = 하루 합계 하나만 있어 “오늘 숫자가 내 평소 범위 안인가”만 볼 수 있는 상태. 같은 지표라도 두 경로의 값은 눈금이 달라 비교·차감하지 않습니다.

저해상도 대체 경로는 생활여유에만 있습니다. 자기돌봄은 시간대가 없으면 기회 자체를 정의할 수 없어 산출 불가, 일상안정은 해상도보다 이력 기간이 관건입니다.

질문으로 대체

자기돌봄은 일반 자가보고(어려움 응답 등 평점)로 대체할 수 없습니다. 어려움 응답은 생활여유·일상안정에만 들어갑니다. 식사 시각만 응답으로 받으면 “기준점 확인됨”까지이며, “식후에 움직였는지”까지 구조화해 물으면 보고 경로로 산출은 가능하나 저해상도·별도 눈금이고 자가보고를 실제 연결로 인정할지는 미확정(9장 B-3).

09 · Open Items

확인 항목 · 미확정 과제

확정된 것: 지표명 · 정의 · 구성 요소 · 공통 원칙 · 필수/옵션 데이터 · 수집 현황. 아래는 ‘구현 착수’ 전에 확인하거나 정해야 하는 값입니다. A-1이 갈림길 — 이 답에 따라 생활여유 고해상도·자기돌봄이 열리는지 정해집니다.

A · 데이터 확보 개발팀

A-1 · 걸음·심박·활동시간의 수집 형태

일별 총량인지 시간대별 샘플인지. 시간대 샘플이면 생활여유 고해상도·자기돌봄이 열리고, 총량이면 일상안정만 완전 성립 + 생활여유 저해상도

최우선
A-2 · 활동 구간 샘플 재구성

기존 걸음·심박 raw 샘플을 15분 이하 버킷으로 받아 구간별 cadence·%HRmax로 중·고강도 분류. 새 권한 불필요. 폰-only 사용자의 버킷 크기·품질과 ‘10분 bout’ 판정 가능 여부 확인

개발
A-3 · 식사 시각 확보 방식

센서 추정 불가. ① 긴 비활동 종료 시점을 기준점으로 ② 하루 1회 가벼운 질문 ③ 둘 다 — 어느 조합으로 갈지

기획
A-4 · 생년월일 연동

최초 정보 연동 시 실제로 들어오는지, 미연동 사용자 폴백(%HRmax 경로 비활성)

확인
A-5 · 심박 형태

안정 시 심박(일별 대표값)인지 시계열인지. 일상안정 신호·생활여유 신뢰도 보강에는 안정 시 값 필요

확인
A-6 · 플랫폼 차이

운동 기록(세션)은 애플만, 활동 시간·BMI는 삼성만 — 플랫폼별로 자기돌봄 기준점 후보·해상도가 달라지는 것을 어떻게 다룰지

확인
A-7 · 수집하지만 안 쓰는 항목

혈압·혈당·체지방률·BMI·키 — 3지표 산출 미사용. 맥락·안전장치·화면 표시 범위를 어디까지로 할지

방침

B · 산출 규칙 기획 · 개발 · 의학팀 · 캘리브레이션

B-1 · 계수의 기준 문서

이 기획서는 ‘계수 미확정’인데 현행 엔진 v5.7에는 고정 계수가 있음(2장 참고). 엔진 값을 초기 기준으로 채택할지, 백지에서 캘리브레이션할지

결정 필요
B-2 · 생활여유 저해상도 경로 채택

걸음 합계만으로 35~65 범위 값을 띄울지, ‘관찰 중’으로 둘지. 파이프라인 문서는 “걸음 총량만으론 산출 안 함”이라 불일치

결정 필요
B-3 · 자기돌봄 자가보고 인정 범위

구조화된 보고(“점심 12:30, 이후 걸었음”)를 실제 연결로 인정할지. 회의록 “실제 행동 연결 미확인 시 좋은 상태로 안 올림”과의 경계

결정 필요
B-4 · 자기돌봄 관찰 창

기준점 이후 몇 분(엔진 30분)까지를 연결로 볼지. 근거는 “되도록 이른 편”이라는 방향만

의학팀
B-5 · 기준선 윈도우 통일

엔진 = 최근 7일 + 직전 21일(28일) / 파이프라인 = 30일 분포 / 기획서 = 미확정. 하나로. 신호별 최소 관찰일(체중은 느슨하게)도 함께

결정 필요
B-6 · 내부 값 → 상태 경계

상태 3단계 경계를 사용자 분포·해석 유용성 기준으로 캘리브레이션. 저해상도 경로는 별도 눈금

캘리브레이션
B-7 · 방향 임계값

▲/유지/▼ 판정 임계를 노이즈 수준 분석으로 조정. 일상안정은 주 단위

캘리브레이션
B-8 · 재계산 주기 · 스냅샷

1일 1회 + 동기화 시 재계산 여부, 주간 스냅샷 확정 시각, 정의 변경 시 버전 태그

확인
B-9 · 신규 사용자 기준 형성 기간

가입 직후 ‘관찰 중’으로만 표시되는 기간을 며칠로 둘지

확인

C · 문서 정합 지표 기획서 ↔ 산출 파이프라인 ↔ 엔진

C-1 · 지표 2 이름

기획서 자기돌봄 / 파이프라인 건강돌봄 — 하나로

결정 필요
C-2 · 일상안정 성격

기획서 = 방향(안정 쪽 ↔ 쏠림 쪽, 양방향) / 파이프라인 = 변동성(안정적 ↔ 불안정, 체중·심박 입력, 변동성·이탈 산식). 회의록 원문은 “어느 방향으로”

결정 필요
C-3 · 결과값 어휘

기획서 짧은 명사형(빠듯·보통·충분 등) / 파이프라인 문장형(충분해요·부족해요·잘하고 있어요). 말풍선용 ~요형은 문구 규칙에서 별도 변환

결정 필요
C-4 · 엔진 표기 갱신

v5.7 시나리오 실험실은 I1/I2/I3 · 생활 여력/행동 기회 연결/개인 기준 변화 표기 — 확정 지표명으로

개발
C-5 · 데이터 모델

데이터모델 문서는 아직 metric_score — metric_state·metric_baseline로

문서

D · 화면 · 감수

D-1 · 화면 문구 · 앱 화면 구현

정의 필요
D-2 · 지표명 임상·평가 오인 감수

생활여유·자기돌봄·일상안정이 진단명·평가 점수로 읽히지 않는지(MRS 9장). 특히 ‘안정’이 상태로 읽히는 문제는 부제로 잡음

감수
D-3 · 저해상도 사용자 화면

폰만 쓰는 사용자에게 ‘참고’ 배지·방향 생략·짧은 문구를 어떻게 보여줄지. 워치 없는 사용자를 불리하게 보이지 않게(P2)

화면

팀 논의 때 확인할 점

  • 세 지표가 사용자를 평가하는 말투가 아니라 자기 이해를 돕는 말투로 설명되는가?
  • 2번 지표의 최종 이름이 사용자의 주체성을 긍정적으로 표현하는가?
  • 질문이 없어도 디바이스 중심 해석이 가능한 구조로 이해되는가?
  • 기록 유무가 점수 보너스로 오해되지 않는가?
  • 세 지표를 합산 점수로 만들지 않는 방향에 팀이 동의하는가?
  • 사용자에게 보여줄 상태 표현이 숫자보다 이해하기 쉬운가?
