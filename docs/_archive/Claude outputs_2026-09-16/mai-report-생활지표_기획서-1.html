1개요 · 지표 체계의 목적

왜 3개의 지표로 나누는가, 그리고 각 지표는 서로 어떤 층위를 대표하는가

1.1 기획 배경

마이리포트 v1은 검진·진료 이력을 조회하는 기록 열람 중심 서비스였다. v2는 여기에 AI 웰니스 코칭을 더해, 사용자가 매일 자신의 생활 데이터를 스스로 해석하고 행동을 조정할 수 있도록 돕는 것을 목표로 한다. 이때 코칭이 설득력을 가지려면 "지금 내 상태가 어떤지"를 사용자가 직관적으로 확인할 수 있는 근거 지표가 필요하며, 이 3종 지표가 그 역할을 한다.

세 지표는 사용자의 하루를 평가하거나 줄 세우기 위한 점수가 아니다. 사용자가 자신의 생활 흐름을 이해하고, 조절 가능한 지점을 알아차리도록 돕는 해석 지표다. 현재 단계에서 확정된 것은 지표의 방향과 구성 원칙이며, 최종 점수 계수·화면 문구·데이터 저장 구조·앱 화면 구현은 계속 조정 중이다.

1.2 왜 지표가 3개이며, 왜 하나로 합치지 않는가

세 지표는 같은 데이터(걸음 수·활동·수면·심박)를 다른 시간축과 다른 질문으로 바라본 결과다. 하나의 종합 점수로 합치면 "오늘 컨디션이 안 좋아서"인지 "최근 행동을 안 해서"인지 "최근 며칠 흐름이 달라져서"인지 구분할 수 없게 되므로, 층위를 분리해 유지한다. 평균이나 합산으로 하나의 점수를 만들지 않고, 세 지표를 나란히 보면서 생활의 관계를 이해하는 방식을 취한다.

예시 — 생활여유는 낮지만 자기돌봄은 괜찮을 수 있다(하루가 빠듯했지만 가능한 순간마다 작은 행동을 붙였다는 뜻). 반대로 생활여유는 괜찮지만 일상안정이 낮을 수도 있다(오늘은 버틸 만하지만 최근 흐름은 한쪽으로 몰리고 있다는 뜻). 세 지표는 서로를 대신하지 않으며, 차이를 함께 봐야 생활 상태를 더 정확히 설명할 수 있다.
노출 명칭은 생활여유(I1) · 자기돌봄(I2) · 일상안정(I3)이다. 내부 코드 I1/I2/I3는 산식·데이터 설계에서만 쓰고 사용자 화면에는 노출하지 않는다. 명칭은 평가·압박형 표현(점수·순응도·의지력)을 피하고 사용자가 자기 생활에 대입해 읽을 수 있는 말을 고른다는 원칙으로 정했다.

1.3 공통 설계 원칙

질문은 보조 정보다

질문 응답은 지표를 직접 올리거나 내리는 입력이 아니라 이유 설명·맥락·신뢰도 보강용이다. 질문이 없어도 지표는 가능한 범위에서 표시되며, 답변이 없다는 이유만으로 낮은 점수를 주지 않는다.

디바이스 데이터가 기본 축

현재 수집 가능한 디바이스 데이터가 지표 계산의 기본 축이다. 다만 watch 미보유 사용자를 불리하게 만들지 않는다 — watch가 있으면 더 자세히, 없으면 더 낮은 해상도로 해석한다.

기록은 점수 보너스가 아니다

식사 기록처럼 사용자가 직접 남긴 기록은 "기록했다는 사실" 자체로 점수를 올리지 않는다. 기록이 있으면 특정 생활 순간을 더 잘 알아볼 수 있을 뿐이며, 실제 행동 연결이 확인된 것으로 보지 않는다.

숫자는 내부 계산용이다

내부적으로 계산용 값을 가질 수 있으나, 사용자에게 정밀 숫자를 그대로 보여주지 않는다. "충분해요 / 보통이에요 / 부족해요"처럼 이해 가능한 상태 표현을 우선한다.

결측은 실패가 아니다

데이터가 없으면 0이나 실패로 치환하지 않고 null 또는 [low, high] 범위로 보존한다. 산출 불가(null)는 정상 상태이며, 다른 창·비례 점수로 메우지 않는다(차트에는 빈 구간으로 표시).

룰 베이스로 시작

실사용 데이터로 학습할 환경이 아직 없어 초기 버전은 미리 정한 규칙과 안전장치로 움직인다. 계수(35/85·M·G·H·D·Q 등)는 고정 규칙값이며 데이터로 학습한 값이 아니다. 실사용 데이터는 추후 이상 반응 확인·보정에만 쓴다.

I1

생활여유 (내부명: I1 · 생활 여력도 / Life Margin)

정의

수면, 활동, 휴식 등 최근 생활 데이터를 바탕으로 현재 일상에서 느낄 수 있는 부담과 여유의 균형을 보여주는 지표. 생활 부담(몸이나 하루가 한쪽으로 몰려 있는 상태)과 생활 여유(하루 중간중간 부담을 풀어주는 작은 여백)를 함께 본다.

목적

사용자가 "지금 내 하루를 이어갈 여유가 충분한가?"를 직관적으로 확인하게 해, 오늘의 코칭·오늘의 목표 제안의 근거로 사용한다.

활동 시간·운동 시간의 플랫폼별 정의 (SDK 문서 확인, 2026-09)
· Apple HealthKit — '활동 시간' 항목은 없다. appleExerciseTime은 "빠르게 걷기 이상 강도의 움직임을 1분 단위로 누적"한 값으로 Apple Watch가 자동 기록하며, HKWorkoutSession도 합산된다(iOS에서 저장한 워크아웃은 duration 전체가 운동 링에 더해짐). Watch가 없으면 생성되지 않는다.
· Samsung Health Data SDK — ActivitySummaryType.TOTAL_ACTIVE_TIME은 "활동에 쓴 총 시간"으로 폰·워치·핏·링 데이터를 중복 없이 합산하며 강도 기준이 없다. ExerciseType.TOTAL_DURATION은 운동 세션 합계이고, 워치의 자동 감지(10분 이상 걷기·달리기 등)도 세션으로 기록된다.
· 따라서 movement_minutes(활동 시간)는 두 플랫폼 값을 쓰지 않고 걸음 interval에서 직접 산출해 정의를 통일하고, 운동 시간·운동 기록은 세션 기반(HKWorkout / ExerciseType)만 쓴다. Apple의 운동 시간과 Samsung의 활동 시간을 같은 축에서 비교하지 않는다.

구성 요소

구성 요소쉬운 설명지표에서의 역할
비활동 압력 (G)오래 앉아 있거나 움직임이 적어 하루가 굳어 있는 정도여력을 낮추는 핵심 요소
늦은 시간·몰린 활동 (H)활동이 너무 늦거나 한 시점에 몰린 정도부담을 키우는 보조 요소
분산된 가벼운 움직임 (M)하루 중간중간 짧게 움직이거나 흐름을 끊어준 정도여력을 높이는 핵심 요소
수면 부족 (D)필요한 수준에 비해 수면이 부족했는지여력을 낮추는 요소
주관적 부담 (Q)사용자가 오늘 일상활동을 어렵게 느꼈는지(질문 응답)이유 설명과 해석 보강

산출방식

웨어러블 원본 데이터를 그대로 더하지 않고 위 중간값으로 변환한 뒤, 데이터 풍부도에 따라 두 갈래 경로 중 하나로 계산한다.

① 풍부한 타임라인 경로
clip( 50 + (35/85) × (35·M − 30·G − 20·H) − 20·D + 12·Q , 0, 100 )

기준 50에서 시작해 (35M−30G−20H)를 35/85(≈0.41)로 축소 반영, 수면·응답 보정 후 0~100으로 자른다. 활동 총량이 아니라 M·G·H = 하루의 배치가 핵심이다.

② 희소 기록·자가보고 경로 (걸음수만, 또는 응답만)
50 + clip( 8·R + 12·Q , −15, 15 )

R = 평소 기록 범위와의 익숙함(오늘 기록이 내 평소 밴드 안인가). 보정폭이 ±15로 묶여 이 경로의 I1은 항상 35~65 사이. 예: 걸음 14,720 · 수면/응답 없음 → I1 43.9(low_resolution_life_margin_rule).

두 경로는 절대 눈금이 동등하지 않다 — 타임라인 경로의 60점과 기록경로의 60점을 비교·차감하지 않는다.

이 지표가 말하지 않는 것

생활여유는 피로도, 수면 점수, 스트레스 점수, 회복 점수, readiness 점수가 아니다. 치료 효과나 건강 상태를 판단하는 지표도 아니다.

예시

하루 걸음 수가 많아도 늦은 시간에 몰려 있고 중간에 쉬는 흐름이 없다면 "여력이 충분하다"고 단정하지 않는다. 반대로 활동량이 아주 많지 않아도 하루 중간에 가벼운 움직임과 쉬는 흐름이 분산되어 있으면 여력이 어느 정도 유지된 것으로 본다.

결측 처리

타임라인이 불완전하면 rich 경로 대신 희소 기록 경로로 대체한다. 데이터가 없다고 0점으로 채우지 않는다.

데이터 흐름도

원본 웨어러블 데이터 → M/G/H/D/Q 중간값 변환 → 풍부/희소 경로 분기 산식 → 0~100 규칙값 → 홈/생활 탭 상태 문구 노출
I2

자기돌봄 (내부명: I2 · 기준점-행동 연결 지표)

정의

사용자의 건강 상태와 생활 맥락을 기준으로, 사용자가 조절할 수 있었던 생활 순간(기준점)에 실제 행동이 얼마나 연결됐는지를 보여주는 지표. 단순히 많이 움직였는지가 아니라 "행동할 수 있는 순간"과 "그 근처에서 실제로 일어난 행동"의 연결을 본다.

최종 이름은 사용자의 주체성을 긍정적으로 표현해야 한다는 것이 원칙이었다("의지력"·"순응도"·"실천 점수" 등 평가·압박형 표현은 배제) — 노출명은 자기돌봄으로 확정.

목적

"나는 지금 내 건강을 위해 필요한 행동을 하고 있나?"에 답해, 목표 수행·권장 행동·생활습관 실천 정도를 사용자가 확인하게 한다.

구성 요소

구성 요소쉬운 설명지표에서의 역할
조절 가능한 기준점식사, 긴 비활동, 일정 전후처럼 행동을 붙일 수 있는 순간행동 연결을 볼 수 있는 출발점
기준점 근처의 실제 행동기준점 전후에 실제 움직임이나 조절 행동이 있었는지지표를 움직이는 핵심 요소
행동의 배치행동이 하루 안에서 어느 위치에 놓였는지해석을 보강하는 요소
반복되는 연결비슷한 연결이 여러 번 나타나는지하루 해석의 안정성을 높이는 요소
기록 유무사용자가 식사 같은 기준점을 기록했는지평가 가능성과 이유 설명 보강

산출방식

(오늘 확인된 '연결된' 행동 수) / (해당 기회 수) × 100 // 예: 기회 3회 중 2회에 행동이 붙음 → 66.67

기회 목록과 결과가 충분히 관측될 때만 값을 낸다. 부족하면 산출 불가(null) — 다른 날 점수로 대체하지 않는다. 걸음 수만으로는 계산이 불가하다(식사·활동의 시간 관계가 없어 '기회'를 정의하지 못함). 어려움 응답 평점은 들어가지 않으며, 실제 행동-기회 연결만 본다.

하위 변형: 일별 연결 / 7일 전체(7일이 다 있을 때) / 관측 부분(빠진 날 제외한 나머지 기회만 — 전체 값의 대체 아님). 화면에는 일별 연결만 표시한다.

기록만 있는 경우

식사 기록만 있고 실제 움직임 데이터가 없다면 "식사라는 기준점은 확인됨" 정도로 본다. 이것은 기록했다는 행위에 대한 낮은 수준의 인정이지 점수 보너스가 아니다. 실제 행동 연결이 확인되지 않았기 때문에 좋은 상태로 올리지 않는다.

이 지표가 말하지 않는 것

자기돌봄은 의지력 평가가 아니다. 코칭 순응도, 목표 달성률, 활동량 점수도 아니다. 활동량이 많아도 기준점과 연결되지 않으면 좋은 상태로 단정하지 않는다.

예시

하루 총 걸음 수가 많아도 식사나 긴 비활동 뒤의 행동 연결이 보이지 않으면 이 지표는 크게 움직이지 않을 수 있다. 식사 기록이 있고 그 뒤 가까운 시간에 짧은 걷기나 움직임이 확인되면, 그때는 행동 연결로 본다.

결측 처리

미확인 credit은 midpoint(중간값)로 임의 치환하지 않는다. 기회 목록 자체가 불완전하면 정밀 비율을 계산하지 않고 null로 둔다.

데이터 흐름도

기준점 후보(식사·비활동 등) + 실제 행동 데이터 → 기준점-행동 매칭 → 연결 수/기회 수 비율 → 일별 연결률(0~100) → 화면 노출
I3

일상안정 (내부명: I3 · 생활 변화 방향도 / Personal Baseline Shift)

정의

일정 기간 동안 수면, 활동, 체중, 심박 등 생활 데이터가 평소의 패턴과 비교해 얼마나 안정적으로 유지되고 있는지, 즉 최근 생활 신호가 나에게 맞는 방향으로 쌓이고 있는지를 보는 지표.

목적

"최근 내 생활 흐름은 얼마나 안정적으로 이어지고 있나?"에 답해, 당일 상태(I1)·당일 행동(I2)과 달리 여러 날에 걸친 변화의 방향을 보여준다. 생활 탭 주간 추이·스파크라인의 핵심 근거가 된다.

무엇을 보나

정해진 목표에 얼마나 맞췄는지를 보지 않는다. 사람마다 생활 리듬과 가능한 활동 범위가 다르므로 하나의 고정된 기준으로 판단하지 않고, 최근 신호가 개인의 평소 범위 안에서 안정되는지, 반복되던 막힘이 줄어드는지, 반대 방향의 신호가 커지는지를 본다.

구성 요소

구성 요소쉬운 설명지표에서의 역할
개인 기준 범위그 사람에게 평소 자연스러운 생활 신호의 범위변화 판단의 기준
최근 벗어남 (B)최근 신호가 개인 기준에서 어느 방향으로 벗어났는지변화 방향을 보는 핵심 요소
반복되는 막힘의 완화늦은 활동, 긴 비활동, 흐름 끊김 같은 문제가 반복적으로 줄어드는지긍정 방향을 보강
반대 신호와 흔들림좋아 보이는 신호와 나빠 보이는 신호가 함께 있는지과도한 해석을 막는 요소
어려움 응답 변화 (Q)최근-기준 구간의 어려움 응답 변화변화 방향 보강

상대·비단조 특성 — 기준 이력이 이미 나빴던 사람은 지금도 나빠도 I3가 덜 낮게 나올 수 있다. 현재 상태가 아니라 방향을 보는 지표이기 때문이다.

이 지표가 말하지 않는 것

일상안정은 오늘의 몸 상태나 오늘의 활동량 점수가 아니다. 목표 달성률도 아니고, 치료 효과를 말하지도 않는다. 하루만 좋아졌다고 해서 좋은 변화가 쌓이고 있다고 판단하지 않는다 — 반복되는 방향성이 확인되어야 한다.

예시

어느 하루에만 걸음 수가 늘어난 것은 긍정 변화로 단정하지 않는다. 반면 며칠 동안 늦은 시간의 몰린 활동이 줄고, 긴 비활동 뒤 가벼운 움직임이 반복적으로 붙는다면 생활 변화 방향이 나아지는 흐름으로 본다.

결측 처리

baseline 15일·recent 5일의 동일 의미 기록이 확보될 때만 계산한다. point score 산출이 불가능하면 score_bounds(범위)로 전달하며, 이 범위는 신뢰구간이 아니라 관측 가능한 성분 조합의 점수 범위임에 유의한다.

운영 계층(수집) → 전처리 계약(정규화) → 산식 계층(I1/I2/I3, 본 기획서 범위) → 노출 계층(홈/생활 탭) — 결측 처리 원칙은 전 계층에 공통 적용
세 지표를 관통하는 공통 규칙 — 기준점 50은 건강 판정 경계가 아니다(0–100은 제품 규칙값이지 임상 점수가 아니다). 입력은 지표별로 선택 반영되며(어려움 응답 → I1·I3만 / 걸음수만 → I1 저해상도 경로만 / 식후 걷기 → I2·I3), 관측 경로가 다르면 비교 자체를 하지 않는다(comparable 플래그로 비교 차단). 세 지표는 끝까지 합산·평균하지 않으며, 계수(35/85·35·30·20·8·12·20 등 clip 경계)는 전부 고정 규칙값으로 이 데이터로 학습한 값이 아니다.

7지표 흐름 탐색기 (보조 시각화 자료)

한 사람의 연속 데이터로 산식 동작을 직접 확인하는 인터랙티브 자료 — 팀 내 산식 이해·QA 용도

본 기획서의 산식(§2~4)이 실제 데이터에서 어떻게 움직이는지 확인할 수 있도록, 합성 42일 데이터 기반의 탐색기를 별도 HTML로 제공한다. 두 개의 탭으로 구성한다.

① 42일 데이터 흐름 탭

한 사람의 연속 42일 걸음·수면·활동 데이터로부터 I1·I2·I3가 날짜별로 어떻게 변하는지 확인한다. 특정 날짜를 선택하면 그날의 세부 성분(M/G/H/D/Q, 기회 수와 연결 수, B/Q 변화량, 결측 처리 상태)까지 분해해서 보여준다.

② 조건·시나리오 비교 탭

동일 기준일에서 걸음 분산·수면 부족·식후 움직임·타임라인 결측 여부를 바꿔가며 기준 조건 대비 결과가 어떻게 달라지는지 비교한다. 사전 시나리오로 식후 움직임 추가, 늦은 시간 활동 몰림, 타임라인 결측, 기록만 있고 행동 없음을 준비한다.

탐색기로 확인해야 하는 핵심 동작
