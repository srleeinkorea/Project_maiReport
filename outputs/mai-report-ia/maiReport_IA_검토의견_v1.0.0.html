01 · Standalone / Google Sites

독립 문서 · Google Sites 게시 관점

Google Sites는 외부 HTML을 샌드박스 iframe(고정 높이, 스크립트·상위창 접근 제한)으로 임베드합니다. 현재 IA 문서는 화면 목록과 프로세스 흐름을 자바스크립트로 그리기 때문에, 스크립트가 실행되지 않거나 제한되면 본문이 비어 보입니다. 아래 항목을 반영해 ‘스크립트 없이도 완전히 읽히는’ 정적 문서로 만들어야 합니다.

G1본문(화면 트리·프로세스 흐름)이 런타임 스크립트로 생성됨Blocker
위치
<div id="groups"></div>, <div class="flows" id="flows"></div> 는 빈 컨테이너이고, <script> 안의 render() 와 groups/flowData 배열이 실행 시점에 모든 노드를 innerHTML로 채움
영향
Google Sites 임베드에서 인라인 스크립트가 차단·지연·실패하면 화면 인벤토리 전체(약 51개)와 7개 업무 프로세스가 표시되지 않음. 히어로·상위 구조·필터 UI만 남아 사실상 빈 문서가 됨
권장
모든 노드와 흐름을 정적 HTML 마크업으로 프리렌더. 데이터 배열은 문서 생성 시점에 HTML로 펼쳐 두고, 스크립트는 검색·필터의 선택적 향상으로만 남김(없어도 전체가 보이도록)
G2검색·필터·초기화 컨트롤이 스크립트 전제High
위치
#search 입력, .chip[data-filter] 영역 필터, #reset 버튼 — 모두 addEventListener 로만 동작
영향
스크립트 미실행 시 클릭·입력해도 반응이 없는 ‘죽은 UI’로 남아 문서 신뢰도를 떨어뜨림
권장
정적 렌더에서는 전체 노출이 기본이 되게 하고, 필터 바는 기본 hidden 후 스크립트가 있을 때만 노출(<noscript> 대비). 또는 임베드 전용 버전에서 필터 바 제거
G3‘내보내기’ 버튼이 window.print() 의존Medium
위치
<button id="print" ... >내보내기</button> → window.print()
영향
샌드박스 iframe에서 상위창 인쇄가 막히면 무반응. 사용자가 고장으로 인식
권장
사이트 게시 버전에서는 버튼 제거, 또는 “원본 파일에서만 동작” 안내. 인쇄가 필요하면 페이지 자체를 인쇄 친화적으로 두고 브라우저 메뉴 이용 안내
G4고정 헤더(position:sticky) · backdrop-filter 프리픽스 누락Medium
위치
.top{position:sticky;top:0;backdrop-filter:blur(18px)...} (프리픽스 -webkit-backdrop-filter 없음)
영향
고정 높이 iframe 안에서 sticky는 이점이 거의 없고 상단이 잘릴 수 있음. Safari/일부 WebKit에서 블러 미적용
권장
임베드 변형에서는 헤더를 position:static. 블러 유지 시 -webkit-backdrop-filter 병기
G5브랜드 폰트가 선언만 되고 로드되지 않음Medium
위치
font-family:Pretendard,"Noto Sans KR",... 이지만 @font-face·웹폰트 링크 없음
영향
대부분 환경에서 Malgun Gothic/Arial로 조용히 폴백 → 다른 산출물과 자모 간격·굵기 인상이 달라짐
권장
독립 문서 원칙상 외부 요청 없이: (a) 시스템 스택으로 명시하고 폴백을 수용하거나, (b) 브랜드 일치가 중요하면 woff2를 @font-face + base64로 문서에 내장. 외부 Google Fonts 링크는 ‘외부 요청 0’ 원칙에 어긋나므로 지양
G6임베드 높이 계약 없음Low
위치
문서 전체 길이가 가변(약 A4 여러 장 분량)
영향
Google Sites 임베드는 높이가 고정 → 내부 스크롤 발생, 트리 카드가 이중 스크롤됨. iframe 자동 리사이즈는 상위창 통신이 필요해 대개 불가
권장
가능하면 임베드가 아닌 전체 페이지로 게시(파일 업로드 또는 페이지 본문 전환). 임베드해야 하면 권장 높이를 함께 안내하고, 섹션을 접이식(<details>)으로 만들어 초기 높이를 줄임
G7외부 자원 의존도 — 현재는 양호, 기준으로 고정Low
확인
현재 이미지·CDN·외부 CSS/JS 요청 없음(스타일·스크립트 모두 인라인). 아이콘도 유니코드 문자 사용
권장
이 상태를 표준으로 유지. 이후 아이콘 추가 시 인라인 SVG, 이미지 필요 시 base64 data: URI
비(非)코드 주의: footer에 Internal Use Only 표기가 있습니다. Google Sites에 올릴 경우 해당 사이트/페이지의 공개 범위가 사내로 제한돼 있는지 먼저 확인하세요. 방금 작성한 MRS 문서에도 동일 표기가 있습니다.

04 · Standard

‘독립적 문서’ 표준 — 향후 전 문서 공통

IA·기능정의서·MRS 등 앞으로 제공하는 모든 HTML 산출물이 충족해야 하는 기준입니다. Google Sites 임베드/게시, 오프라인 열람, 파일 단독 전달에서 모두 동일하게 동작하도록 합니다.

  • 외부 요청 0. 폰트·CSS·JS·이미지·아이콘을 전부 인라인/시스템으로. 이미지는 base64 data: URI, 아이콘은 인라인 SVG 또는 유니코드
  • 정적 우선. 콘텐츠는 HTML 마크업으로 완결. JS를 꺼도 100% 읽힘. JS는 검색·필터·접힘 등 향상 전용이며 <noscript> 또는 기본 노출로 대비
  • 브라우저 특권 동작에 핵심 기능을 걸지 않음. window.print()·window.open() 등은 보조 기능으로만
  • iframe 안전. position:fixed 금지, sticky는 임베드 변형에서 static, 벤더 프리픽스 병기(-webkit-backdrop-filter 등), 합리적 min-height
  • 딥링크. 주요 섹션·항목마다 안정적인 id(scr-*, sec-* 규칙)를 부여해 목차·상호 참조 가능하게
  • 접근성. 색만으로 정보 전달 금지, 상태에는 텍스트 라벨, 본문 대비 AA 충족, lang="ko", <title>, <meta name="description">
  • 단일 스타일시트. <style> 하나, 토큰 1회 정의, 죽은 규칙 없음
  • 링크 정책. 문서 세트를 함께 올릴 때는 상대경로 유지, 그 외에는 전체 URL. 깨진 내부 링크 없음
  • 메타데이터. footer에 발행일·버전·기밀등급 명시, 히어로 기준일과 일치
  • 인쇄는 부가. @media print는 유지하되 화면 뷰가 정본. 스케일 핵 대신 재배치 사용
참고: 방금 전달한 MRS 문서는 본문이 정적이라 G1은 해당 없음. 다만 G3(window.print() 버튼), G4(sticky 헤더 + 프리픽스), G5(폰트 미로딩)는 동일하게 적용되므로 같은 기준으로 손보는 것을 권장합니다.
