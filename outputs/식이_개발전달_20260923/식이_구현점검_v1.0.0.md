# 식이 구현 기준 및 남은 결정 — v1.0.0

## 적용 범위

이 폴더의 데이터 계약 엑셀이 개발 기준이다. `diet-selection-v1.0.0.mjs`는 날짜·답변 재사용·식후 후보 판정의 실행 가능한 참조 코드이며, HTML 화면은 시연용이다. 실제 서버의 저장, 전체 축 우선순위, 검진 판정 엔진까지 연결된 운영 앱은 이 산출물에 포함되지 않는다.

앱은 개인 처방식과 식품 알레르기 정보를 수집하지 않는다. 따라서 두 정보를 이용한 개인화 판정은 계약에 두지 않는다. 일반 식품 목표 문구는 기존 질환별 금지, 시간, 상황 조건에 따라 사용한다.

## 확인 후 바로잡은 구현 오류

| 항목 | 문제가 되는 사례 | v1.0.0 구현 기준 |
|---|---|---|
| 지난 끼니와 세션 날짜 | 23일 03:00과 04:00에 모두 22일 저녁을 묻지만 세션은 서로 다름 | 응답은 `(user_id, meal_date, meal_type, question_id, question_version)`의 현재 유효 답 1건을 재사용한다. 목표와 완료 기록은 04:00 경계 `session_date`로 묶는다. |
| 식후 목표 | 22:00에 내일 아침 목표를 지금 완료하라는 식의 화면 | 17:00~04:00에는 실제 식후 행동 후보 10개만 사용한다. `READY`, 시간, 달력, 상황, 질환별 금지 조건을 모두 통과한 후보가 없으면 `GUIDANCE_ONLY`다. |
| 주말 판정 | 토요일 01:00은 금요일 세션이므로 금요일 목표로 오판 | 평일·주말은 목표 행동의 현지 **달력 날짜**로 판정한다. 세션 귀속 날짜와 분리한다. 명절·연휴 및 별도 상황값이 필요한 문구는 현재 입력 자료가 없어 보류한다. |
| 노출조건 상태 | 실제 데이터의 `NEED_CONTEXT_CALENDAR`를 검증 규칙이 허용하지 않음 | 실제 상태 코드를 검증 규칙에 맞추고 `READY` 137개만 기본 자동 후보로 둔다. 나머지 39개는 입력 조건이 마련될 때까지 보류한다. `READY`도 실행 시각과 날짜로 다시 검사한다. |
| 검진 신호와 목표 문구 | FPG·BP·TC·BMI의 축은 연결돼 있는데 전용 문구 ID가 없어 목표 전체가 막힘 | 기존 축 문구 풀을 재사용한다. FPG→Q01, BP→Q03, TC→Q07, BMI 25 이상→Q05. 통과 후보가 없으면 안내만 표시한다. 검진 데이터는 검진일로부터 달력 기준 3개월 이내인 경우만 식이 목표 선정에 사용한다. |
| 사용하지 않는 입력·승인 필드 | 앱이 받지 않는 알레르기·개인 처방식이나 전문의 출시 승인값에 따라 문구를 숨김 | 이 입력과 승인 스위치를 목표 선정 계약에서 제거했다. 기존 질환별 금지 및 문구 상태 판정은 유지한다. |

## 데이터 검증

- 질문 8개에 선택지 24개가 연결돼 있으며 질문마다 정확히 3개다. 고아 선택지는 없다.
- 목표 문구 176개와 노출조건 176개가 버전 키로 일대일 연결된다. 식후 대상 10개는 모두 `READY`다.
- `diet-selection-v1.0.0.test.mjs`의 경계 시각, 자정 이후 주말 판정, 답변 재사용, 후보 없음 검사가 4개 모두 통과했다.
- 두 시연 HTML의 인라인 JavaScript 구문 검사를 통과했다. 시연 HTML의 목표 선정은 일부 하드코딩되어 있으므로 운영용 전체 후보 엔진을 대신하지 않는다.

## 운영 전 남은 결정

다음은 원본 데이터나 정책이 없으면 임의로 정할 수 없어 `결정필요` 시트에 남긴 항목이다.

| ID | 개발 시 영향 | 필요한 입력 |
|---|---|---|
| I-07 | 상병 코드 두 조건의 동시 성립을 잘못 판정할 수 있음 | AND/OR, 같은 진료 여부, 유효 기간과 우선순위 |
| I-08 | 저혈당 처치용 단 음료를 평소 식이 답변으로 오해할 수 있음 | 처치 상황 수집 여부 또는 해당 축 집계 보류 규칙 |
| I-10 | 문장형 설정 일부의 분모·관찰 기간이 불명확함 | 부분 구조화 항목의 실행 순서와 충돌 해결 |
| I-13 | 긴 이유 문구가 화면에서 잘릴 수 있음 | 실제 화면 폭·줄 수 기준 |
| I-15·I-16 | 경계 밖 검사값과 소수점 값을 자의적으로 정상 판정할 위험 | 검사값 정밀도·반올림 및 `UNCLASSIFIED` 화면 처리 확정 |
| I-18·I-19 | 또래 등수 또는 성별 분기값을 신뢰할 수 없음 | 분포 데이터 버전·표본 수·성별 입력 출처 |
| I-20 | 보조 지질 문구의 인용 판본 확인이 남음 | 해당 자료의 문구 대조 |
| I-21·I-22 | 검진기관 판정 원문과 다른 단위의 수치를 안정적으로 변환할 수 없음 | 기관 코드 사전, 허용 단위·변환식·정밀도 |

사용자 시간대가 세션 중 바뀌는 경우에는 `diet_session.timezone_id`를 기록할 수 있지만, **기존 세션을 유지할지 새 세션을 만들지**의 전환 정책은 별도로 확정해야 한다. 이 정책을 임의로 구현하지 않는다.

현재 설정은 후보가 없어 `GUIDANCE_ONLY`인 날도 완료율의 분모에 넣고 미완료로 센다. 실제 목표가 없는데 사용자의 미완료처럼 보일 수 있으므로, 목표분석 화면을 운영하기 전에 이 집계 정책을 확정해야 한다.
