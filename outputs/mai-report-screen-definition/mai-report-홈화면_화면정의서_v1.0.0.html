홈 화면 화면정의서

홈은 데이터를 보여주는 화면이 아니라 "오늘 무엇을 할지 정해주는 화면"이다. 오늘의 질문 → 오늘의 코칭 → 오늘의 목표 → 오늘의 컨디션 → 오늘의 건강 데이터 순으로 결론과 실행을 먼저 두고, 근거는 뒤에 둔다. 이 문서는 각 영역의 구성·상태·문구·연동 규칙을 정의한다.

1화면 개요

홈의 역할과 영역 순서

1.1 화면의 역할

사용자가 앱을 열었을 때 30초 안에 "오늘 내 상태가 어떤지 → 오늘 무엇을 하면 되는지"를 알고 나갈 수 있어야 한다. 수치 해석은 생활 탭이 맡고, 홈은 결론과 실행만 보여준다.

3오늘의 질문

기기 데이터로 알 수 없거나 부족한 상태를 보완하는 하루 5문항 미만의 질문. 모든 문항에 답하면 코칭과 잠긴 목표가 한 번에 생성된다

3.1 구성

  • 구성 요소: 진행 표시("오늘의 질문 · n/N", N은 그날 문항 수) · 질문 · 문항 일러스트 · 선택지 3개.
  • 한 번에 1문항. 선택하면 잠시 선택 상태를 보여준 뒤 다음 문항으로 자동 전환.

3.2 문항 생성 원칙

문항과 선택지는 고정 세트가 아니다. 그날 연동된 기기 데이터에서 부족하거나 확인되지 않은 상태를 골라, 그것을 보완하는 질문을 만든다. 따라서 사용자마다, 날마다 문항이 다르다.

① 데이터 파악오늘 수집된 기기 데이터(걸음·수면·심박·활동 등)와 의료 이력을 확인
② 확인할 상태 선정결측·부족 항목과 기기로 알 수 없는 주관 상태를 우선
③ 선택형 질문 생성한 번에 답할 수 있는 3지선다. 하루 5문항 미만
④ 답변 활용모두 답하면 코칭·잠긴 목표 생성(1회), 수치 답변은 데이터로 저장

수면 데이터가 이미 있으면 수면 문항은 내지 않는 식으로, 기기로 알 수 있는 것은 묻지 않는다. 단 식사 문항은 매일 고정으로 포함한다. 식이는 기기로 알 수 있는 데이터가 없어 식이 목표를 만들려면 답변이 반드시 필요하기 때문이다. 나머지 문항은 부족한 항목에서 고른다. 하루 문항 수는 5문항 미만으로 두되, 컨디션 지표 산출이나 코칭에 필요한 상태가 늘어나면 문항 종류가 추가될 수 있다. 문항 풀·선정 규칙·문구는 별도 문서(오늘의 질문 생성 규칙)에서 확정한다.

3.3 상태

상태내용
진행 중현재 문항 히어로. 답하지 않은 문항은 하루 동안 그대로 남는다.
모두 완료"오늘의 질문 완료 / 잘 했어요 👍 답변을 모두 완료했어요!" + 클립보드 일러스트 + 카드 「오늘 답변 모두 보기 › · 오늘의 몸 상태를 계속 유지해 봐요!」
답변 수정답변 보기 화면에서 언제든 수정. 수정 시 코칭을 다시 생성하고, 답변으로 만들어진 목표도 수정된 답변으로 다시 만든다. 기기 데이터로 만들어진 목표와 이미 완료한 목표는 바꾸지 않는다(§5.4).

3.4 세트 확정 시점

  • 그날의 문항 세트(5문항 미만)는 첫 진입 시 그 시점의 데이터 부족분으로 한 번 정하고 바꾸지 않는다.
  • 문구는 시간대에 맞춘다. 아침·낮은 현재형, 18시 이후 첫 진입은 과거형. 하루 경계는 새벽 4시.
  • 목표 완료 여부는 질문으로 묻지 않는다(완료는 타일에서만 기록).

4오늘의 코칭

화면의 주인공. 오늘 실천할 핵심 행동 한 줄

4.1 구성

라벨 "오늘의 코칭" · 핵심 행동 한 줄로 구성한다. 이유나 근거 문장은 붙이지 않는다.

4.2 상태 3단계

상태문구비고
① 답변 전먼저 오늘의 질문에 답하고,
나에게 맞는 코칭을 받아보세요.		모든 문항에 답하기 전까지 그대로 유지. 일부 답변 상태에서 코칭·목표는 생성·변경되지 않는다
② 생성 중(생성 중 표시)마지막 답변 직후부터 응답 도착까지
③ 결과핵심 행동 한 줄모든 문항 답변 완료 시점에 코칭과 잠긴 목표를 함께 1회 생성. 답변 수정 시 ②→③ 반복. 답변으로 만들어진 목표도 함께 다시 생성(§5.4)

4.3 생성 규칙

결과 문구는 그날의 질문 답변과 기기 데이터를 종합해 생성한다. 조건별 우선순위와 문구 세트는 별도 문서(코칭 생성 규칙)에서 확정한다.

코칭은 모든 문항에 답한 시점에 한 번 생성되며, 답변을 수정하지 않는 한 그날 바뀌지 않는다. 낮 동안 기기 데이터가 갱신되어도 코칭 문구는 다시 만들지 않는다. 저녁(18시 이후)에 생성되는 경우에는 남은 시간에 맞는 마무리형 문구를 쓴다.

5오늘의 목표

식이 · 활동 · 수면 각 1개. 홈과 생활 탭 > 목표 분석이 같은 타일 컴포넌트를 쓴다

5.1 구성

섹션 제목 "오늘의 목표"와 "n/3 완료 ›"(탭 → 생활 탭 > 목표 분석). 목표 타일 3개(식이·활동·수면). 타일에는 카테고리와 목표 문구만 두고 근거·비교 문구·연속일수는 쓰지 않는다.

5.2 타일 상태

상태내용동작
기본카테고리 · 목표 문구탭 → 완료
완료완료 표시. 목표 문구는 그대로 읽을 수 있어야 함(취소선 없음)탭 → 완료 취소
잠김카테고리 · "오늘의 질문에 답하면 목표가 생성돼요." · 잠금 표시탭 → 남은 질문으로 이동

목표 상태는 완료 / 미완료 두 가지뿐이다. '쉬기' 상태는 두지 않으며, 완료하지 않은 날은 미완료로 집계한다.

5.3 잠금 규칙(질문 보완 생성)

목표별로 필요한 기기 데이터가 충분하면 첫 진입 시 바로 생성해 보여주고, 부족하면 그 목표만 잠근다. 잠긴 목표는 문항마다 하나씩 열리지 않고, 그날의 질문에 모두 답한 시점에 코칭과 함께 한 번에 생성된다. 식이 목표는 기기 데이터로 만들 수 없으므로 항상 잠긴 채 시작하고, 매일 고정으로 나오는 식사 문항을 포함한 질문에 답해야 생성된다. 활동·수면은 데이터 충족 여부로 매일 판정하며, 이 둘까지 모두 잠그지는 않는다.

목표기기 데이터가 있으면 첫 진입 시 생성부족하면
식이해당 없음 — 기기 데이터로 만들지 않는다항상 잠금 → 질문(식사 문항 고정 포함) 완료 시 검진 결과 + 답변으로 생성
활동걸음·활동 시간이 오늘 수집될 때잠금 → 질문 완료 시 생성
수면어젯밤 수면 기록이 있을 때잠금 → 질문 완료 시 생성

잠긴 타일을 누르면 남은 질문으로 이동한다. 일부만 답한 상태에서는 어떤 목표도 생성·변경되지 않는다.

5.4 생성 · 고정 규칙

  • 목표는 그날 첫 진입 시 그 시점의 데이터와 답변으로 만들고, 그날은 문구를 바꾸지 않는다(사용자와의 약속). 연속일수도 이 고정된 목표를 기준으로 센다.
  • 하루 경계는 새벽 4시. 저녁(18시 이후) 첫 진입이면 남은 시간 안에 할 수 있는 형태로 생성한다.
  • 낮 동안의 데이터 변화는 목표 문구를 바꾸지 않는다. 걸음 데이터로 목표를 넘었더라도 타일에 별도 표시를 하지 않으며, 완료는 사용자가 직접 누른다(자동 완료 없음).
  • 질문 전체 답변 완료 시점에 잠긴 목표만 답변을 반영해 생성한다. 첫 진입 때 기기 데이터로 이미 만들어진 목표는 답변이 들어와도 절대 바꾸지 않는다. 답변으로 만들어진 목표는 답변에 종속되므로, 답변을 수정하면 수정된 답변으로 다시 만든다. 단 이미 완료 처리한 목표는 내용과 상태를 유지한다. 낮 동안의 기기 데이터 변화만으로는 어떤 목표도 다시 만들지 않는다.

5.5 문구 생성

목표 문구와 숫자는 기기 데이터(최근 개인 기록)와 질문 답변으로 산출한다. 카테고리별 문구 세트와 산출 규칙은 별도 문서(목표 생성 규칙)에서 확정한다.

6오늘의 컨디션

생활여유 · 자기돌봄 · 일상안정 세 지표의 오늘 상태. 숫자 없이 세 구간으로만 보여준다

6.1 구성

섹션 제목 "오늘의 컨디션"과 "›"(탭 → 생활 탭 > 지표별 분석). 지표 3개(생활여유 · 자기돌봄 · 일상안정) 각각 지표명 · 3구간 게이지 · 구간 라벨로 구성. 항상 펼쳐진 상태이며 접힘/펼침 없음. 전일 대비(▲▼·변화 없음), 점수, 이유 문장, 핵심 데이터는 홈에 두지 않는다.

6.2 3구간 게이지

주의 · 보통 · 좋음 세 구간 중 현재 구간 하나를 가리키는 게이지. 숫자·눈금값은 표시하지 않는다. 산정 불가 시 아무 구간도 가리키지 않는 빈 상태로 둔다.

6.3 지표와 라벨

지표한 줄 정의(? 토글)구간 라벨 좋음 / 보통 / 주의
생활여유오늘 남아 있는 몸의 여유충분해요보통이에요부족해요
자기돌봄오늘 나를 챙긴 정도잘하고 있어요보통이에요부족해요
일상안정최근 생활 리듬의 일정함안정적이에요비슷해요불안정해요

구간 경계는 잠정 66 / 33(0~100 내부 규칙값). 지표 정의·산식·부연 설명은 생활지표_기획서, 지표별 카드 규칙은 지표별분석_화면정의서를 따른다. 홈에서는 정의 문장을 노출하지 않는다.

6.4 요약 문장 노출 조건

세 라벨이 이미 상태를 말하므로 평상시에는 요약 문장을 두지 않는다. 다음 경우에만 한 줄을 붙인다.

조건문구
주의 구간 지표 있음{지표명}에서 살펴볼 점이 있어요.
관찰 중 지표 있음{지표명}은 아직 관찰 중이에요. + 지표별 사유 한 줄 (요약 문장은 붙이지 않음)
세 지표 모두 관찰 중아직 관찰 중이에요. 며칠 더 쌓이면 상태를 보여드릴게요. (요약 문장은 붙이지 않음)

6.5 산정 불가 · 미연동 처리

관찰 중(데이터 부족)

빈 게이지 + 라벨 "관찰 중" + §6.4 문구. 결측을 0이나 낮은 구간으로 치환하지 않고, 다른 날 값으로 메우지 않는다. 지표별 사유 문구는 지표 산출 규칙에 따라 정한다.

건강 데이터 미연동

게이지 대신 연동 안내: "건강 데이터를 연동하면 오늘의 컨디션을 볼 수 있어요 / 걸음·수면·심박 데이터로 생활여유 · 자기돌봄 · 일상안정을 계산해 드려요 [건강 데이터 연동하기]". 관찰 중과 반드시 구분한다.

7오늘의 건강 데이터

대표 3개만 홈에, 나머지는 전체 건강 데이터 화면에서

7.1 홈 구성

섹션 제목 "오늘의 건강 데이터"와 "›"(탭 → 전체 건강 데이터). 섹션 우측에 보조 라벨 "어제 대비". 걸음 수 · 수면 시간 · 안정 시 심박수 3개 행이 고정 순서로 놓인다. 각 행 = 항목 아이콘 · 항목명 · 오늘 값(숫자 + 단위) · 어제 대비 문구. 행 자체는 누르는 동작이 없다(이동은 §7.2).

홈에서는 해석이나 조언을 붙이지 않는다. "오늘 얼마인가"와 "어제보다 어떤가" 두 가지만 말하고, 의미 해석은 컨디션(§6)과 코칭(§4)이 맡는다.

7.1.1 값 정의

세 항목 모두 연동된 건강 앱에서 읽어 온 값을 그대로 쓴다. 앱이 추정하거나 보정하지 않는다.

항목오늘 값의 정의표기갱신
걸음 수오늘 자정(0시)부터 지금 시각까지 누적된 걸음 합계. 건강 앱의 달력일 집계와 같은 숫자여야 한다. 새벽 4시 경계를 적용하지 않는다천 단위 구분 정수 + "걸음". 예: 6,420 걸음홈 진입·재진입 시. 하루 동안 계속 늘어난다
수면 시간어젯밤 수면 세션의 총 수면 시간(잠든 시간만, 깬 구간 제외). 오늘 새벽 4시 이전에 시작해 오늘에 끝난 세션을 "어젯밤"으로 본다. 세션이 여러 개면 합산하되 낮잠(정오~18시 사이 시작)은 제외"n시간 m분". 1시간 미만이면 "m분". 예: 7시간 20분기상 후 수면 세션이 동기화되면 한 번 확정. 그날 값이 바뀌지 않는다
안정 시 심박수애플 — 애플 워치가 전달한 오늘의 안정 시 심박 값을 그대로 쓴다. 삼성 — 안정 시 값을 주지 않으므로 심박 샘플에서 직접 산출한다(생활지표 기획서 2.1: 하루의 심박 샘플을 5분 평균으로 묶어 가장 낮은 값). 하루가 끝난 뒤 확정되므로 삼성에서는 마지막으로 확정된 날의 값이 보인다. 어느 쪽도 값이 없으면 "기록 없음"으로 두고 수면 구간 평균으로 대체하지 않는다정수 + "bpm". 예: 68 bpm애플 — 건강 앱 값이 갱신될 때마다, 보통 하루 1회. 삼성 — 하루가 끝난 뒤 1회 확정

단위는 값 뒤에 작게 붙이고 항목명에는 단위를 쓰지 않는다. 걸음 수는 "지금까지" 누적이므로 오전에는 작은 값이 정상이다. 비교(§7.1.2)는 어제 하루 전체와 하므로, 하루가 지나면서 차이가 줄어드는 것이 자연스러운 흐름이다.

새벽 4시 하루 경계는 질문·코칭·목표의 하루 단위와 수면의 귀속일에만 쓴다. 건강 데이터 표시값에는 쓰지 않는다. 걸음 수는 건강 앱과 같은 자정 기준이어야 두 숫자가 어긋나지 않고, 하루 합계만 주는 기기에서는 4시 기준으로 나눌 방법도 없기 때문이다.

7.1.2 어제 대비(비교) 정의

기준은 어제 값이다. 권고치(예: 1만 걸음, 7시간), 또래 평균, 여러 날 평균과 비교하지 않는다. 오늘과 어제 두 값만 있으면 계산되므로 연동 다음 날부터 바로 보이고, 사용자가 "어제보다"라는 기준을 직관적으로 이해한다.

항목비교 대상(어제 값)차이 표기
걸음 수어제 하루 전체 걸음 합계(어제 0시~24시, 자정 기준). 시각을 맞추지 않고 오늘 지금까지 누적과 어제 하루 합계를 그대로 비교한다. 시간대별 기록이 없는 기기에서도 같은 방식으로 계산된다걸음 수 절대값(천 단위 구분). "▲ 820걸음" / "▼ 1,240걸음". 백분율은 쓰지 않는다
수면 시간그저께 밤(어제 표시값)의 총 수면 시간분 단위(60분 이상이면 "n시간 m분"). "▲ 35분" / "▼ 1시간 10분"
안정 시 심박수어제의 안정 시 심박 대표값bpm 정수. "▲ 5bpm" / "▼ 4bpm"

비교 문구는 방향 기호와 차이 숫자만 쓴다. "많아요·적어요·길어요·높아요" 같은 서술어는 붙이지 않고, "비슷해요" 같은 폭 판정도 두지 않는다. 차이가 정확히 0이면 방향 기호 없이 "· 어제와 같음"으로 쓴다. ▲는 오늘 값이 어제보다 큼, ▼는 작음을 뜻할 뿐이며, 좋다·나쁘다를 뜻하는 색이나 표현은 쓰지 않는다. 걸음이 많은 것, 심박이 낮은 것을 홈에서 좋은 것으로 단정하지 않기 위해서다. 어제 값이 0이면 비교하지 않고 "어제 기록 없음"으로 처리한다.

상태비교 문구
오늘 · 어제 모두 있음위 규칙대로 비교 문구 표시
어제 값 없음"어제 기록 없음". 오늘 값은 그대로 보여준다. 그저께 이전 값으로 대신 비교하지 않는다
오늘 값 없음값 자리에 "—", 비교 문구 자리에 "기록 없음". 걸음 수는 자정 이후 첫 동기화 전, 수면은 어젯밤 세션이 없을 때, 심박은 오늘 대표값이 없을 때
기기 미착용 의심어젯밤 수면과 오늘 심박이 모두 없고 걸음만 있으면(휴대폰만 소지) 수면·심박 행에 "기록 없음"을 두되 미연동 안내로 바꾸지 않는다
건강 데이터 미연동세 행 대신 §6.5와 같은 연동 안내 카드 한 장. 컨디션 영역과 안내를 중복해서 두 번 보여주지 않고, 컨디션 영역에 안내가 있으면 이 영역은 숨긴다

"평소 대비"(여러 날 기준선과의 비교)는 홈에서 쓰지 않는다. 평소 범위와의 비교는 컨디션 지표(§6)와 생활 탭이 맡는다. 어제 하루가 특이했던 날(여행·휴일 등)에는 비교 문구가 크게 흔들릴 수 있으나, 홈은 해석 없이 사실만 보여주므로 그대로 둔다.

7.2 이동 화면

섹션 제목의 "›"를 누르면 전체 건강 데이터 목록으로 이동한다. 전체 목록 화면은 홈이 아니므로 구성은 별도 화면정의서(건강 데이터)에서 정의한다.
