1화면 개요

위치, 역할, 화면 구조

1.1 위치와 역할

생활 탭의 세 번째 서브탭(목표 분석 · 지표별 분석 · 생활 분석 · AI 인사이트). 지표별 분석이 "왜 그런 상태인지"를 설명한다면, 생활 분석은 "실제 값이 어땠는지"를 보여준다. 사용자가 자주 보는 4개 항목을 먼저 보여주고, 나머지 항목은 전체 건강 데이터에서 확인한다.

1.2 화면 구조

상단 공통생활 헤더(주차 · 오늘 버튼) · 날짜 스트립 · 서브탭
연동 상태 바연동된 소스 이름 · 동기화 상태 · 연동 해제 (연동된 경우에만)
대표 항목 카드 4개걸음수 → 활동 칼로리 → 심박수 → 수면 (순서 고정)
전체 건강 데이터 진입"전체 건강 데이터 ›" (체중 · 체지방률 · 혈압 · 혈당 등)
전체 건강 데이터 목록4그룹 12항목, 행 탭 → 항목 상세
항목 상세기간 탭 · 선택 값 · 그래프 · 기간 요약

1.3 기준일

날짜 스트립에서 선택한 날이 기준일이다. 대표 항목 카드의 "오늘 값"은 기준일 값으로 바뀌고 라벨도 "8월 19일 걸음수"처럼 날짜로 바뀐다. 이전 주로 이동하면 그 주 일요일이 기준일이며 읽기 전용이다. 전체 건강 데이터 목록과 항목 상세는 기준일과 무관하게 항상 오늘을 기본으로 연다.

2.1 연동 상태 바

생활 분석 콘텐츠 맨 위에 둔다. 안드로이드는 연동 소스가 삼성헬스와 헬스 커넥트 두 가지라서, 지금 어떤 소스가 연결돼 있는지와 동기화 상태를 항상 보여준다. iOS는 소스가 건강 앱 하나이므로 이름만 다르고 구성은 같다.

요소동작
소스 이름"삼성헬스 연동됨" / "헬스 커넥트 연동됨" / (iOS) "건강 앱 연동됨". 한 번에 하나의 소스만 연동된다
동기화 상태동기화 중이면 "동기화 중…"(진행 표시), 끝나면 "동기화 완료 · n분 전". 완료 상태를 탭하면 수동으로 다시 동기화한다. 앱 진입·탭 진입 시 자동 동기화
연동 해제연동된 상태에서도 항상 노출. 탭 → 해제 확인 시트("{소스} 연동을 해제할까요?") → 해제 시 미연동 상태로 전환. 소스를 바꾸려면(헬스 커넥트 → 삼성헬스 등) 해제 후 다시 연동한다
미연동상태 바 대신 연동 안내 카드. "건강 데이터 연동하기" → 소스 선택 시트(삼성헬스 / 헬스 커넥트, iOS는 생략) → 권한 시트 → 연동 완료 후 동기화 시작

5전체 건강 데이터 목록

연동된 항목을 그룹별로 보여주는 별도 화면

5.1 구성

제목 "전체 건강 데이터" + 뒤로가기. 그룹별 목록(항목명 · 오늘 값 · ›). 행을 누르면 항목 상세로 이동한다. 연동 기기·앱 이름은 어디에도 쓰지 않는다.

그룹항목오늘 값 형식
활동걸음 수 · 활동 칼로리 · 활동/운동 시간 · 운동 기록7,340 걸음 · 320 kcal · 42 분 · 3회
심박 · 수면심박수 · 수면63 bpm · 7시간 23분

하단 안내: "연결한 건강 앱에서 제공되는 항목만 표시돼요. 활동 시간은 걸음 기록에서 직접 계산하고 운동 시간은 운동 세션 기준이라, 연동한 건강 앱에 보이는 값과 조금 다를 수 있어요."

5.2 항목 제공 원칙

  • 연동한 건강 앱이 제공하지 않는 항목은 목록에서 숨긴다(빈 값으로 두지 않음).
  • 활동 시간은 플랫폼 값을 쓰지 않고 걸음 interval에서 직접 산출한 값을 쓴다. 운동 시간·운동 기록은 운동 세션 기반 값만 쓴다(플랫폼별 정의 차이는 생활지표_기획서 참조).
  • 체중·체지방률·키처럼 매일 기록되지 않는 항목은 최근 등록값을 보여준다.
