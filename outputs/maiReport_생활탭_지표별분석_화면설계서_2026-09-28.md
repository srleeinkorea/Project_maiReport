## 1. 화면 목적

사용자가 이번 주 생활 지표의 상태, 주간 흐름, 해석 근거를 지표별로 이해할 수 있게 한다. 점수 숫자나 종합 건강 등급 대신 지표별 상태 라벨과 짧은 해석 문장을 보여준다.

## 2. 화면 구성

1. **화면 제목 및 기간**: `지표별 분석`, 선택한 주의 날짜 범위
2. **주간 탐색**: 이전/다음 주 이동. 미래 주 이동은 비활성. 진행 중인 주는 `이번 주 현재까지`로 표시
3. **상태 안내**: 데이터 연동/부분 수집/기록 없음 등 필요한 경우에만 표시
4. **지표 카드 3개**: 생활여유, 자기돌봄, 일상안정 순서
5. 카드 구성: 지표명과 기준, 상태 배지, 주간 상태 흐름, 이번 주 해석 한 문장, 핵심 근거 데이터 및 제외 데이터 안내

## 3. 카드 표시 예시

```text
생활여유                              [충분해요]
이번 주 상태 흐름       월 ●  화 ●  수 ●  목 ●  금 ·  토 ·  일 ·
이번 주 해석
움직임이 하루 여러 시간대에 나뉘어 관찰되고, 수면도 개인 기준에 가까웠어요.

이번 주 근거
움직임 기록일 5일 · 수면 7시간 20분
수면 기록 일부가 부족해 이번 해석은 활동 기록을 중심으로 했어요.
```

점과 색은 상태를 보조한다. 색만으로 의미를 전달하지 않으며, 각 점은 스크린리더에 `월요일: 충분해요` 같이 읽히도록 한다. 일상안정은 지표 단위가 주간이므로 요일별 상태 점을 표시하지 않는다.

## 4. 점수 경계와 상태 라벨

점수는 서버/지표 산출기가 **지표별로 다른 경계표**를 적용해 구간으로 변환한다. I1·I2·I3에 공통 임계값을 적용하면 안 된다. 화면은 점수 숫자를 표시하지 않고, 전달된 `state_key`를 해당 지표의 라벨과 연결한다. 구간 판정의 입력은 각 지표의 정규화된 표시 점수이며, 화면은 점수를 다시 계산하거나 공통 경계로 재판정하지 않는다.

| 지표 | 낮은 구간 (`low`) | 가운데 구간 (`mid`) | 높은 구간 (`good`) |
|---|---:|---:|---:|
| 생활여유 (I1) | `< 40` → 부족해요 | `40 이상, 70 미만` → 보통이에요 | `>= 70` → 충분해요 |
| 자기돌봄 (I2) | `< 33` → 부족해요 | `33 이상, 66 미만` → 보통이에요 | `>= 66` → 잘하고 있어요 |
| 일상안정 (I3) | `< 33` → 불안정해요 | `33 이상, 66 미만` → 비슷해요 | `>= 66` → 안정적이에요 |

경계값 자체는 상위 구간에 포함된다. 즉 I1 40은 `mid`, 70은 `good`; I2/I3 33은 `mid`, 66은 `good`이다.

## 5. 이번 주 해석 분기 조건

### 표시 우선순위

```text
1) 과거 주를 보는 중이면 해당 주 스냅샷을 읽기 전용으로 표시한다.
2) 동기화 중이면 상태 라벨 대신 “기록을 불러오고 있어요”를 표시한다.
3) `observation_sufficiency != sufficient`, 상태 산출 불가 또는 충돌 입력이면 `state_key`와 무관하게 “관찰 중”을 표시한다.
4) I2에서 유효한 행동 기회와 완료 근거가 없으면 “관찰 중”으로 표시한다.
5) 충분도와 필수 근거 검사를 통과하면 산출기가 반환한 3구간 상태를 표시한다.
6) `state_key`가 누락되거나 지원되지 않으면 “관찰 중”으로 처리하고 로깅한다.
```

### 상태별 기본 문장

| 지표 | state_key | 상태 배지 | 이번 주 해석 기본 문장 |
|---|---|---|---|
| I1 | good | 충분해요 | “이번 주는 움직임과 휴식이 비교적 균형 있게 이어졌어요.” |
| I1 | mid | 보통이에요 | “이번 주 생활 흐름은 평소와 비슷해요.” |
| I1 | low | 부족해요 | “이번 주는 움직임이나 회복할 틈이 적게 관찰됐어요.” |
| I2 | good | 잘하고 있어요 | “이번 주에는 계획한 건강 행동이 생활 속에서 이어졌어요.” |
| I2 | mid | 보통이에요 | “이번 주에는 계획한 건강 행동이 일부 확인됐어요.” |
| I2 | low | 부족해요 | “이번 주에는 계획한 건강 행동이 충분히 확인되지 않았어요.” |
| I3 | good | 안정적이에요 | “이번 주 생활 흐름이 평소 범위 안에서 이어졌어요.” |
| I3 | mid | 비슷해요 | “이번 주 생활 흐름은 평소와 크게 다르지 않았어요.” |
| I3 | low | 불안정해요 | “이번 주 생활 흐름이 평소와 다르게 나타났어요.” |

개별 원인(예: 수면 때문에 상태가 낮아짐)은 원인 기여도가 계산되고 검증된 경우에만 덧붙인다. 데이터에서 직접 확인되지 않는 인과 문장은 생성하지 않는다.

### 관찰 중 문구

| 상황 | 표시 문구 |
|---|---|
| 생활여유 근거 부족 | `관찰 중` · “기록이 더 쌓이면 이번 주 생활 흐름을 알려드릴게요.” |
| 자기돌봄 행동 근거 부족 | `관찰 중` · “건강 행동 기록이 더 쌓이면 이번 주 흐름을 알려드릴게요.” |
| 일상안정 기준선 부족 | `관찰 중` · “평소 흐름과 비교할 기록이 더 필요해요.” |
| 데이터 동기화 | `기록을 불러오고 있어요` · “최근 건강 데이터를 가져오고 있어요.” |
| 기간 내 기록 없음 | `기록 없음` · “선택한 기간에는 확인된 생활 기록이 없어요.” |
| 검증 실패/충돌 | `기록 확인 중` · “일부 기록을 확인할 수 없어 해석에 반영하지 않았어요.” |

### 5.1 산출기 점수 구간 판정

다음 경계는 2026-09-28 확정한 v7 기준이다. 지표 ID에 해당하는 경계만 적용한다. 산출 계층에서 구간을 판정해 `state_key`로 반환한다. 경계값은 위 구간에 포함된다. I1에 I2/I3 기준을 적용하거나 그 반대로 적용하지 않는다.

| 지표 | 점수 조건 | `state_key` |
|---|---|---|
| I1 생활여유 | `< 40` | `low` |
| I1 생활여유 | `40 <= 점수 < 70` | `mid` |
| I1 생활여유 | `>= 70` | `good` |
| I2 자기돌봄 | `< 33` | `low` |
| I2 자기돌봄 | `33 <= 점수 < 66` | `mid` |
| I2 자기돌봄 | `>= 66` | `good` |
| I3 일상안정 | `< 33` | `low` |
| I3 일상안정 | `33 <= 점수 < 66` | `mid` |
| I3 일상안정 | `>= 66` | `good` |

경계 QA: I1의 `39.99/40/69.99/70`은 `low/mid/mid/good`, I2·I3의 `32.99/33/65.99/66`도 `low/mid/mid/good`다. 아래 해석 문구 사양은 이 구간값을 사용한다.

### 5.2 이번 주 해석 실제 노출 예시

```text
이번 주 해석 · 9.21–9.27
생활여유                                           [충분해요]
이번 주는 움직임과 휴식이 비교적 균형 있게 이어졌어요.
```

동일한 카드에서 자기돌봄 `mid`는 `[보통이에요]`와 “이번 주에는 계획한 건강 행동이 일부 확인됐어요.”, 일상안정 `low`는 `[불안정해요]`와 “이번 주 생활 흐름이 평소와 다르게 나타났어요.”를 표시한다. 점수 숫자는 표시하지 않는다.
### 이번 주 해석 표시 사양 (디자인·개발 공통)

**목적:** 현재 선택한 주의 상태를 사용자가 한 번에 이해하도록 상태 라벨과 설명 문장 하나를 표시한다. 이 영역은 점수 증감 보고나 건강 진단이 아니다.

**카드 내 배치:** 지표명/기간 바로 아래에 상태 배지를 두고, 그 아래 `이번 주 해석` 소제목과 본문 한 문장을 둔다. 근거 수치와 데이터 제외 안내는 해석 문장 아래 별도 영역에 둔다. 해석 본문에는 점수·점수 경계·내부 코드가 노출되지 않는다.

```text
이번 주 해석 · 9.21–9.27
생활여유                                        [충분해요]
이번 주는 움직임과 휴식이 비교적 균형 있게 이어졌어요.

근거 보기
움직임 기록일 5일 · 수면 7시간 20분
수면 기록 일부가 부족해 이번 해석에는 포함하지 않았어요.
```

**기간 문구:** 주가 완료됐으면 `이번 주 해석 · 9.21–9.27`, 진행 중이면 `이번 주 현재까지 · 9.21–9.24`로 표시한다. 완료되지 않은 이번 주와 지난주 전체를 비교한 증감 문구는 만들지 않는다. 과거 주 조회 시 선택한 주의 저장 상태를 보여주고 현재형 `이번 주` 대신 `선택한 주 해석`을 쓴다.

**문구 선택:** `status`와 충분도 검사를 먼저 통과한 후 지표별 `state_key`에 해당하는 문장을 한 개 표시한다. 상태 변화 설명을 추가해야 할 때는 주간 구간 배열에서 실제 구간 전환이 확인된 경우에만 짧게 붙인다. 점수의 구간 내 등락만으로 문장을 바꾸지 않는다.

| 지표 | good | mid | low |
|---|---|---|---|
| 생활여유 | 충분해요 — “움직임과 휴식이 비교적 균형 있게 이어졌어요.” | 보통이에요 — “이번 주 생활 흐름은 평소와 비슷해요.” | 부족해요 — “이번 주는 움직임이나 회복할 틈이 적게 관찰됐어요.” |
| 자기돌봄 | 잘하고 있어요 — “계획한 건강 행동이 생활 속에서 이어졌어요.” | 보통이에요 — “계획한 건강 행동이 일부 확인됐어요.” | 부족해요 — “계획한 건강 행동이 충분히 확인되지 않았어요.” |
| 일상안정 | 안정적이에요 — “생활 흐름이 평소 범위 안에서 이어졌어요.” | 비슷해요 — “생활 흐름은 평소와 크게 다르지 않았어요.” | 불안정해요 — “생활 흐름이 평소와 다르게 나타났어요.” |

**분기 순서:**

```text
if 과거 주:
    선택한 주의 저장 상태를 읽기 전용 표시
else if syncing:
    “기록을 불러오고 있어요” 표시
else if status != available or observation_sufficiency != sufficient:
    지표별 “관찰 중” 문구 표시
else if I2 and valid_action_evidence != true:
    자기돌봄 “관찰 중” 문구 표시
else if I3 and state threshold/calculation is not approved:
    점수 구간 문구를 쓰지 않고 확인된 사실 요약 또는 “관찰 중” 표시
else:
    state_key에 대응하는 배지 + 문장 표시
```

**관찰 중 기본 카피:** I1 `기록이 더 쌓이면 이번 주 생활 흐름을 알려드릴게요.` / I2 `건강 행동 기록이 더 쌓이면 이번 주 흐름을 알려드릴게요.` / I3 `평소 흐름과 비교할 기록이 더 필요해요.` 구체적으로 남은 일수를 산출할 수 있을 때만 “기록이 2일 더 필요해요”처럼 표시한다.

**근거와 원인 표현:** `evidence`에서 `used=true`인 값만 근거로 표시한다. 최대 2개 핵심 항목을 기본 노출하고 나머지는 `자세히 보기`에 둔다. 제외 항목은 사용자가 결과를 이해하는 데 필요한 경우 “수면 기록이 부족해 이번 해석에는 포함하지 않았어요.”처럼 이유를 안내한다. 데이터 기여도가 계산되지 않으면 “수면이 부족해서 생활여유가 낮아요” 같은 원인 문장은 쓰지 않는다.

**지표별 안전 조건:**

- 생활여유: 활동 시간대 분산을 입력으로 실제 계산한 경우에만 “여러 시간대에 나뉘어”라고 쓴다.
- 자기돌봄: 유효한 행동 기회와 완료 기록이 있어야 3구간 문구를 표시한다. 걸음 수나 움직임만으로 행동 완료를 추정하지 않는다.
- 일상안정: 주간 지표로만 표시한다. 승인된 상태 구간이 없으면 일별 상태 점·화살표 대신 관찰 사실 또는 관찰 중 문구를 쓴다.

**상태 이력:** 월~일 각 날짜의 `state_key`가 있으면 3구간 도트/밴드로 표시하며 결측일은 빈 상태로 둔다. 실제 `low` 상태만 낮은 구간 색을 쓴다. `이번 주 해석` 문장은 선택한 주의 최종 상태를 요약하며, 주간 중 전환이 있었던 경우에는 실제 전환일/전환구간이 제공될 때만 “주 초에는 보통이었고 주 후반에는 충분 구간으로 바뀌었어요.”를 추가한다.

## 6. 주간 흐름 및 탐색

- 월~일 7개 요일 슬롯을 표시한다. 기록이 없는 날은 low 상태로 칠하지 않고 빈 슬롯/미관찰로 표시한다.
- 선택일은 외곽선 등 비색상 방식으로 강조한다.
- 상태 흐름은 숫자 축 없는 3구간 밴드/도트로 나타낸다. 점수·증감 폭은 사용자에게 노출하지 않는다.
- 일상안정은 주간 값만 표시한다. 요일별 상태나 일별 화살표를 만들지 않는다.
- 과거 주는 저장된 스냅샷을 읽기 전용으로 본다. 재산출 여부는 데이터 계약에서 정한다.

## 7. 핵심 데이터 표시

- 지표 산출에 실제 사용한 항목만 `핵심 데이터`로 노출한다.
- 수치에는 단위와 기간을 붙인다: `수면 7시간 20분`, `움직임 기록 5일`.
- 미관측·누락은 0으로 표시하지 않는다.
- 제외 항목이 사용자 해석에 영향을 주는 경우 한 줄로 설명한다: `수면 기록이 부족해 이번 해석에는 포함하지 않았어요.`
- 해당 지표의 상태를 직접 설명하지 않는 보조값은 보조 데이터로 구분하거나 접어둔다.

## 8. 구현 데이터 계약

```json
{
  "indicator_id": "I1",
  "period_start": "2026-09-21",
  "period_end": "2026-09-27",
  "period_complete": true,
  "status": "available",
  "state_key": "good",
  "observation_sufficiency": "sufficient",
  "evidence": [
    { "key": "movement_days", "label": "움직임 기록일", "value": 5, "unit": "일", "used": true }
  ],
  "excluded_reasons": []
}
```

### Enum 및 UI 매핑

- `indicator_id`: `I1 | I2 | I3`
- `status`: `available | observing | syncing | unavailable | invalid`
- `state_key`: `good | mid | low | none`
- `observation_sufficiency`: `sufficient | partial | insufficient`
- `valid_action_evidence`: I2의 행동 기회/완료 근거가 유효한지 나타내는 boolean.
- `state_threshold_version`: 적용 경계 버전. API 응답 및 과거 주 스냅샷에 보존한다.
- `state_key=none`이면 관찰 중 문구를 표시한다.
- 미지정 enum, 불가능한 값, `available`과 `none` 외의 조합 오류는 안전하게 관찰 중으로 처리하고 로깅한다.
- 점수→구간 판정은 지표 산출 계층에서 담당한다. `indicator_id`별 임계 설정을 조회하고 UI는 `state_key`만 렌더링한다. UI에서 공통 임계값으로 재판정하지 않는다.

## 9. UI 상태 전이 의사코드

```typescript
function renderMetricCard(x: MetricState): ViewModel {
  if (x.status === "syncing") return copy.syncing;
  if (x.status === "unavailable") return copy.unavailable;
  if (x.status === "invalid") return copy.invalid;
  if (x.status !== "available" || x.observation_sufficiency !== "sufficient") {
    return observingCopy[x.indicator_id];
  }
  if (x.indicator_id === "I2" && !x.valid_action_evidence) {
    return observingCopy.I2;
  }
  if (x.state_key === "none") return observingCopy[x.indicator_id];
  return copyByIndicatorAndState[x.indicator_id][x.state_key];
}
```

진행 중인 주는 view model에서 제목에 `현재까지`를 붙인다. `period_complete=false`인 기간을 과거 주 전체와 직접 비교하지 않는다. 경계는 UI에 하드코딩하지 않고 산출 계층 설정에 적용하며 `state_threshold_version`으로 기록한다.

## 10. 접근성 및 문구

- 상태는 문장과 텍스트 라벨로 제공하고 색상만으로 구분하지 않는다.
- 한 카드의 핵심 해석은 한 문장으로 제한한다. 구체 수치/기여 데이터는 아래 근거 영역에서 제공한다.
- `불안정해요`는 생활 흐름의 개인 기준과 차이를 말하며, 질병/위험/진단을 뜻하지 않는다는 문맥을 유지한다.
- 자기돌봄은 확인된 기회와 완료 데이터를 사용한다. 걸음이나 활동 총량만으로 완료를 추정하지 않는다.
- 점수, 백분율, 내부 등급 코드 및 종합 점수는 사용자에게 노출하지 않는다.

## 11. GitHub 프로토타입 작업 상태 배지

대상 위치는 요청된 프로토타입의 `#wip-metric` 작업 영역이다. GitHub 연동/개발이 진행 중인 동안 다음 표시를 사용한다.

- 관리자 계정에만 상단 작업 영역 헤더에 `GitHub 작업 중` 배지를 표시한다.
- 일반 사용자와 비관리자 화면에는 이 배지, 편집 진입점, 관리자 안내 텍스트를 렌더링하지 않는다.
- 관리자 여부는 인증된 서버/API 역할로 확인한다. DOM/CSS에서 보이기만 숨기는 방식으로 보안 경계를 만들지 않는다.
- 상태 배지 표시 조건과 GitHub 저장소 또는 Pages의 공개/비공개 권한은 별도 설정이다. `관리자만 보임`은 배지 가시성만 뜻한다.
- 작업이 완료되면 상태 필드를 완료로 바꾸고 배지를 제거하거나 `반영 완료`로 갱신한다.
