01 · Lineage

데이터 계보 — 일반 성인

확진 질환이 없는 사용자에게 도달할 수 있는 전체 경로입니다. 초록은 지금 살아 있는 경로, 노랑은 원천이 없어 막힌 경로, 빨강은 끝까지 갔는데 받아 줄 문구가 없는 경로입니다.

지금 살아 있는 경로 원천이 없어 막힌 경로 끝까지 갔는데 문구가 없음
이 그림의 요지

일반 성인에게 지금 도달 가능한 문구는 수면 1건입니다. 초록 줄이 하나뿐인 것이 그 뜻입니다.

걸음수는 계산까지는 정상적으로 끝나는데 받아 줄 규칙이 없어 버려집니다. 사용자 대부분이 제공하는 데이터가 이것이라, 다른 어떤 항목보다 먼저 메워야 할 공백입니다.

웨어러블 밖

계보를 완성하려면 웨어러블이 아닌 입력 3종이 더 필요합니다 — 생년월일(프로필), 확진 질환(질문), 식사 시각(질문). 특히 생년월일은 나이 조건이 붙은 모든 규칙의 전제라, 없으면 웨어러블 데이터가 아무리 완전해도 문구가 나가지 않습니다.

03 · Trace A

값 추적 A — 오늘

45세 · 확진 없음 · 워치 없음 · 수면 기록만 있는 사용자. 계보의 초록 줄을 실제 값으로 따라갑니다.

① 원천

최근 7일 동안 들어온 값. 09-04와 09-07은 기록이 없다.

sleep_session                     daily_step_total
09-02  23:40 → 06:05   6.4h              6,100
09-03  00:20 → 06:10   5.8h              8,400
09-04  (기록 없음)      —                3,200
09-05  23:10 → 06:40   7.5h             11,000
09-06  00:05 → 06:15   6.2h              5,400
09-07  (기록 없음)      —                7,700
09-08  23:55 → 06:20   6.4h              6,900
② 신호 선택

야간 수면 시간의 신호는 asleep_minutes ÷ 60 하나뿐. 확보됨. 강도 판정과 지속시간 필터는 이 지표에 해당 없음.

③ 창 집계

집계 창은 night. 자정을 넘는 수면은 기상 시각이 속한 날짜에 귀속한다 — 09-03의 00:20 → 06:10은 09-03에 붙는다.

밤별 값   6.4 / 5.8 / — / 7.5 / 6.2 / — / 6.4
④ 관찰 창
  • ✓관찰된 밤 5 ≥ 최소 관찰 5밤
  • ✓7시간 미만인 밤 4 ÷ 5 = 0.8 > 기준 0.5

→ 통과. 대표값 6.4를 규칙 평가로 넘긴다. 이 관찰 조건은 9개 지표 중 유일하게 근거에서 온 값이다.

⑤ 규칙 평가

r_gen_sleep_short

  • ✓대상 general · 확진 확인 불필요
  • ✓나이 18 ≤ 45 < 65
  • ✓구간 value_max = 7 → 6.4 < 7
  • ✓필요 입력 sleep_session 이 24시간 안에 있음
  • ✓안전 게이트 없음 · 그룹 sleep_duration 내 유일
⑥ 출력

「최근 수면 시간이 자주 7시간 아래로 내려가요」

근거 표기 — CSEP Canadian 24-Hour Movement Guidelines (성인 18–64)

같은 사용자의 나머지는 왜 안 나가나

지표계산결과
하루 총 걸음수 = 6,900성공이 지표를 보는 규칙이 0건 → 값이 그대로 버려진다
주간 중강도 · 고강도 시간불가구간 샘플 없음 → 지표 목록에서 제외 → 해당 규칙 자동 미적용
짧고 빠른 보행 구간 수불가동일하게 제외
여기가 설계의 핵심

계산 불가 지표를 0으로 채우지 않고 목록에서 뺐기 때문에 「유산소가 부족해요」 같은 문구가 잘못 나가지 않았습니다. 0으로 채웠다면 이 사용자는 활동 데이터가 없다는 이유만으로 「운동이 부족하다」는 말을 들었을 것입니다.

04 · Trace B

값 추적 B — 구간 확보 후

같은 사용자가 워치를 차기 시작해 activity_interval이 들어옵니다. 같은 네 개의 구간에서 지표 셋이 갈라져 나오는 지점이 이 추적의 핵심입니다.

① 원천

09-08 하루치 구간 샘플. MET이 없으므로 우선순위 2번인 cadence 경로를 쓴다.

구간             길이   걸음    cadence = 걸음 ÷ 분
07:12 – 07:26    14분   1,540   110 /min
12:40 – 12:47     7분     810   116 /min
18:05 – 18:33    28분   3,100   111 /min
20:50 – 20:56     6분     700   117 /min
② 구간 판정

중강도 = cadence [100, 130) → 네 구간 모두 해당. 고강도(130 이상)는 없다.

③ 지속시간 필터

여기서 하나의 원천이 세 갈래로 갈라진다. bout 조건이 지표마다 다르기 때문이다.

지표bout 조건남는 구간그날 값
주간 중강도 시간제한 없음14 · 7 · 28 · 655분
짧고 빠른 보행 수1분 이상 10분 미만7 · 62건
주간 활동일수10분 이상 존재?14 · 28활동일 1
④ 창 집계

7일치를 합산해 주간 중강도 205분, 주간 고강도 0분.

⑤ 규칙 평가
그룹걸린 규칙노출
aerobic_volume중강도 205 ≥ 150 → prio 10
고강도 0 < 75 → prio 20		prio 10 승 → 「더 늘리지 않아도 돼요」
activity_moment짧은 보행 2 ≥ 1「짧게 빠르게 움직인 시간이 있었어요」
sleep_duration수면 6.4 < 7「최근 수면 시간이…」
⑥ 출력

1건 → 3건. 구간 샘플 하나가 붙자 도달 가능한 문구가 세 배가 된다.

이 결과가 확인 요청 항목

고강도가 0분인데도 「더 늘리지 않아도 돼요」가 나갑니다. 중강도와 고강도를 서로 대체 가능하게 본 우선순위 설계(prio 10 vs 20)의 결과인데, 임상적으로 맞는지는 의학팀 확인 대기 항목입니다.

대안은 중강도 + 2 × 고강도 ≥ 150 같은 등가 환산 지표를 새로 정의하는 것입니다.

금지

7분 구간은 「짧은 보행」에는 세지만 「활동일」에는 세지 않습니다. 떨어진 샘플을 이어붙여 10분을 만들면 안 됩니다. 이어붙이는 순간 두 지표가 같은 값이 되어 구분이 사라집니다.

구간 샘플이 없을 때 하루 총 걸음수를 100으로 나눠 활동 시간을 추정하는 폴백으로 만든 값은, 계산은 되더라도 코칭 판정에 넣지 않습니다.

05 · Gated Paths

질환 경로의 게이트

문구 20건 중 14건이 질환 경로에 있습니다. 웨어러블 데이터가 아무리 완전해도 이 게이트를 넘지 못하면 도달하지 않습니다.

대상문구게이트추가로 필요한 웨어러블
일반 성인6건나이 조건만수면 세션 · 활동 구간 샘플
2형 당뇨12건확진 확인 — AI 리포트 소견만으로는 켜지 않는다활동 구간 샘플 · 운동 세션 + 식사 시각 질문
폐렴 회복기2건확진 확인 + 회복기 맥락 + 활동 가능 여부없음 — 질환만으로 뜨는 문구
웨어러블로 풀 수 없는 것

확진 여부와 식사 시각은 어떤 웨어러블도 주지 않습니다. 애플·삼성 플랫폼에 해당 데이터가 없어 앱 질문이 유일한 경로입니다. 당뇨 문구 12건 중 6건은 식사 시각까지 있어야 하므로, 질문 2종이 확보되기 전까지 문구의 70%는 도달 불가입니다.

안전 게이트

확진이 확인돼도 바로 나가지 않는 문구가 있습니다. 고강도 인터벌을 권하는 당뇨 문구와 폐렴 회복기 문구 2건은 심혈관 위험 평가·활동 가능 여부를 서비스가 별도로 확인한 뒤에만 노출합니다. 코칭 세트는 “확인이 필요하다”는 표시만 넘겨줍니다.

06 · Same Data, Other Tier

같은 데이터가 3지표로 갈 때

같은 값, 다른 결론

추적 A의 수면 6.4시간은 코칭 쪽에서 「권고 미달」이 됩니다. 그런데 이 사람이 평소 6.2~6.5시간으로 일정하게 자 왔다면 일상안정 쪽에서는 「안정적이에요」가 됩니다. 모순이 아니라 서로 다른 질문에 답한 것입니다 — 하나는 권고 대비, 다른 하나는 평소 대비 흔들림.

이래서 두 층을 하나의 점수로 합치지 않습니다. 합치면 「권고 미달」과 「평소보다 나아짐」이 상쇄되어 둘 다 사라집니다.

공통 예외

데이터가 부족하면 세 지표 모두 「관찰 중」으로 표시합니다. 나쁜 상태가 아니라 판정하지 않았다는 뜻이며, 워치가 없는 사용자를 불리하게 만들지 않기 위한 처리입니다.

07 · Breakpoints

끊기는 지점 정리

계보에서 흐름이 멈추는 곳은 넷입니다. 원인이 서로 달라 해결 주체도 다릅니다.

끊기는 지점유형영향푸는 주체
걸음수 → 규칙 문구 없음 계산은 끝나는데 받아 줄 규칙이 0건. 사용자 대부분이 주는 데이터라 공백이 가장 크다 의학팀
활동 구간 샘플 미수집 지표 6개 + 3지표의 시간축이 함께 막힌다. 단일 병목으로 가장 크다 개발팀
생년월일 미수집 나이 조건이 붙은 규칙 전부 + %HRmax 신호. 웨어러블이 완전해도 이것 없이는 안 나간다 개발팀
확진 질환 · 식사 시각 질문 필요 문구 20건 중 14건이 이 뒤에 있다. 웨어러블로는 절대 풀리지 않는다 개발팀 · 기획

푸는 순서

순서확보할 것풀리는 것
①생년월일나이 조건 해제 — 이후 모든 단계의 전제
②활동 구간 샘플 강도 구분일반 성인 문구가 1건 → 4건. 3지표의 시간축도 함께 열린다
③걸음수 문구 신설워치 없는 다수 사용자에게 처음으로 활동 코칭이 닿는다
④확진 질환 질문당뇨 6건 · 폐렴 2건 진입
⑤식사 시각 질문당뇨 나머지 6건 + 건강돌봄의 기준점
