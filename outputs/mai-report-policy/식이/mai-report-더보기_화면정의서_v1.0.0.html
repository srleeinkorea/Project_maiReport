1화면 개요

더보기의 역할과 묶음 순서

1.1 화면의 역할

더보기는 하루에 여러 번 여는 화면이 아니다. 필요할 때 들어와 "확인하고 · 바꾸고 · 나간다"는 세 가지만 한다. 건강 데이터 값, 지표 해석, 코칭은 두지 않는다. 목록 항목은 한 줄에 하나씩, 누르면 그 항목만 다루는 화면으로 넘어가는 구조를 지킨다.

1.2 묶음 순서

① 프로필이름 · 내정보 관리
② 연동건강데이터 · 건강검진 · 진료정보
③ 서비스동의 관리 · 알림 관리 · 이용권 관리 · 언어
④ 법적 정보 및 기타서비스 이용 약관 · 개인정보 처리방침 · 개인정보 수집 및 이용동의
⑤ 목록 밖로그아웃 · 앱 버전

위에서 아래로 "나 → 내 데이터 연동 → 앱 사용 설정 → 법적 문서" 순으로 간다. 동의 관리는 서비스 묶음에서 알림 관리와 함께 둔다. 로그아웃은 설정 변경이 아니라 앱을 벗어나는 동작이므로 목록 카드에 넣지 않고 아래에 따로 둔다.

1.3 두 화면의 관계

더보기탭 바에서 진입. 목록만 보여준다
→ 내정보프로필 카드를 누르면 진입. 가입 정보 조회
→ 회원탈퇴내정보 안에서만 진입. 더보기 목록에는 두지 않는다

4상태값 표기

항목 오른쪽에 붙는 값의 규칙

4.1 연동 · 이용권

건강데이터 연동 · 검진 · 진료정보 연동에는 연동 상태를 표시하지 않는다(“연동됨” · “연동 안 함” 등 없음). 연동 여부와 마지막 동기화 시각은 각 연동 화면에서 확인한다.

항목표기
이용권 관리더보기 목록에는 값을 표시하지 않는다. 이용권 관리 화면 안에서 “프로모션 기간” + 둥근 태그 “무상 제공 중”을 보여준다(고정)

4.2 언어

현재 적용 중인 언어 이름을 그 언어로 쓴다(한국어 · English). 지원 언어가 하나뿐인 동안에도 항목을 숨기지 않고 "한국어"를 그대로 보여준다.

4.3 값을 붙이지 않는 항목

건강데이터 · 건강검진 · 진료정보 · 동의 관리 · 알림 관리 · 이용권 관리 · 약관 · 정책 문서 3개에는 상태값을 붙이지 않는다. 동의와 알림은 항목이 여러 개라 한 줄로 요약하면 오해를 만들고, 나머지는 상태가 없기 때문이다.

공지사항 · 문의하기는 더보기 목록에 두지 않는다. 새 공지가 있어도 탭 아이콘에 “읽지 않음” 표시를 두지 않는다. 알림 목록은 더보기에 두지 않고 홈 헤더의 알림 아이콘이 맡는다.

5내정보 구성

가입 정보는 조회하고, 건강 정보의 만성질환은 직접 선택한다

5.1 구성 요소

요소내용
헤더뒤로가기 + 화면 제목 "내정보". 뒤로가기는 더보기로 돌아간다
이름"{이름}님". 이름은 크게, "님"은 작게 붙인다. 가입 시 등록된 이름을 그대로 쓴다
정보 카드생년월일 · 연락처 · 이메일 주소 3행 고정 순서. 왼쪽 항목명, 오른쪽 값. 화살표 없음(누르는 동작 없음)
건강 정보"건강 정보" 묶음의 "관리 중인 질환" 한 줄. 누르면 질환 선택 화면으로 이동. 선택한 질환을 요약하고, 미입력은 "입력하기", 명시적 해당 없음은 "없음"으로 구분한다
회원탈퇴카드 아래 가운데 정렬 텍스트 + 화살표. §7.2

5.2 만성질환 직접 선택

고혈압·당뇨병·이상지질혈증·만성 신장질환의 4개 항목을 복수 선택할 수 있다. "위 질환은 없어요"는 네 선택을 모두 해제하며, 아무 응답도 저장하지 않은 상태와 구분한다. 저장 전 뒤로 가면 편집 초안을 버린다.

직접 선택은 본인 입력으로 진료정보의 진단 후보·사용자 확인과 출처를 분리한다. 여러 질환을 선택하면 화면에 저장된 선택 순서대로 목표 후보를 찾는다. 현재 질환에서 쓸 수 있는 목표가 없으면 다음 직접 선택 질환, 사용자 확인을 거친 진료정보, 3개월 이내 검진 신호, 일반 식이 질문 순서로 이동한다. 같은 질환이 양쪽에 있으면 직접 선택 출처로 한 번만 반영한다.

고혈압·당뇨병·이상지질혈증은 연결 축과 금지 성격에 반영한다. 만성 신장질환은 새 연결 축 없이 섭취 증감·수분 목표의 안전 제외 조건에만 반영한다. 안전 제외 조건은 출처 우선순위와 관계없이 모두 적용한다. 직접 입력을 지우거나 "위 질환은 없어요"로 바꿔도 진료정보에서 온 후보는 유지한다.

저장하면 미완료 식이 목표만 새 조건으로 다시 고르고 완료 목표와 이력은 보존한다. 데이터 필드와 허용 코드는 「식이 개발 전달 데이터계약 v1.0.0」의 내정보질환매핑·테이블정의·필드정의를 따른다.

5.3 항목 순서 근거

본인 확인에 쓰는 정보(생년월일) → 연락 수단(연락처 · 이메일) 순이다. 지표 계산에 쓰이는 성별 · 키 · 체중은 이 화면에 두지 않는다. 그 값들은 건강 데이터와 검진 결과에서 오고, 바뀌는 주기도 다르기 때문이다.

6.2 값이 없을 때

값이 없는 행도 숨기지 않고 자리를 지키며 "등록 안 됨"으로 쓴다. 어떤 정보가 비어 있는지 사용자가 알 수 있어야 하기 때문이다. 이름이 없으면 "님"만 남기지 않고 화면 제목과 같은 자리를 비운 채 카드부터 보여준다.

6.3 수정

가입 정보 3개 행은 조회 전용이다. 건강 정보의 만성질환 행은 선택 화면으로 이동한다. 생년월일 · 연락처는 본인 확인을 거친 가입 정보라 앱 안에서 바로 바꾸지 않는다.

이름 · 생년월일 · 연락처 · 이메일은 카카오 계정에서 연동해 오는 값이라 앱 안에서 바꿀 수 없다. 별도 안내 문구는 두지 않는다.

③ 로그인 화면기기에 저장된 로그인 정보만 지운다

로그아웃은 서버에 쌓인 기록 · 리포트 · 연동 설정을 지우지 않는다. 다시 로그인하면 이전 상태로 돌아온다. 건강 데이터 연동은 기기 권한이므로 로그아웃으로 해제하지 않는다.

7.2 회원탈퇴

① 내정보에서 탭"회원탈퇴 ›". 더보기 목록에는 진입점을 두지 않는다
② 확인“정말 탈퇴하시겠어요? / 회원탈퇴 시 모든 개인정보가 삭제되며 복구할 수 없어요.” · [탈퇴하기] [취소]. 별도 안내 화면은 두지 않는다
③ 완료로그인 화면으로. 완료 안내 한 줄
탈퇴 시 처리(화면에 나누어 보여주지 않음)내용
사라지는 것계정과 가입 정보, 질문 답변 · 목표 기록 · 지표 · 검진 · 진료 기록. 다시 가입해도 복구되지 않는다
멈추는 것건강 데이터 수집과 모든 알림. 마케팅 수신 동의도 함께 철회된다
남는 것법령에 따라 보관 기간이 정해진 기록. 보관 항목과 기간은 개인정보 처리방침을 따른다

보관 항목 · 기간 등 세부 내용은 개인정보 처리방침 · 약관 고지로 대신한다.

8예외 상태

값을 못 읽거나 이동할 수 없을 때
상황처리
네트워크 없음 · 조회 실패목록 구조는 그대로 두고 상태값 자리만 비운다. 항목을 누르면 이동한 화면에서 각자 오류를 안내한다. 더보기 전체를 오류 화면으로 덮지 않는다
내정보 조회 실패이름과 카드 자리를 비운 채 다시 시도할 수 있게 한다. 이전에 받아 둔 값을 그대로 보여주지 않는다
건강 데이터 미연동더보기에는 표시하지 않는다. 더보기에서는 연동을 권유하지 않는다(권유는 홈 · 생활 탭의 안내 카드가 맡는다)
지원 언어 1개항목을 숨기지 않는다. 선택 화면에 현재 언어 한 줄만 보여준다
로그인 만료더보기 진입 시 로그인 화면으로 보낸다. 빈 값으로 목록을 보여주지 않는다

9화면 이동 규칙

들어오고 나가는 경로 정리
트리거결과
하단 탭 "더보기"더보기 진입. 하위 화면에 있다가 다시 누르면 더보기 목록으로 돌아온다
프로필 카드 탭내정보로 이동
내정보 뒤로가기더보기 목록으로. 스크롤 위치 유지
연동 상태 변경 후 복귀더보기에는 연동 상태를 표시하지 않으므로 갱신할 값이 없다
이용권 구매 · 사용 후 복귀현재 버전은 해당 없음(무상 제공 중에는 갱신할 값이 없다)
언어 선택 후 복귀선택한 언어로 전체 화면 문구를 바꾸고 더보기로 돌아온다
동의 철회 후 복귀더보기 목록은 그대로. 처리 결과는 알림(필수 안내)으로 따로 알린다
로그아웃 · 탈퇴 완료로그인 화면. 뒤로가기로 더보기에 돌아올 수 없다
