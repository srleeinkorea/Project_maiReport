알림 정책

마이리포트의 알림은 사용자를 재촉하는 도구가 아니라 "오늘 볼 것이 준비됐다"를 알리는 신호다. 이 문서는 어떤 알림을 언제 보내고, 하루에 몇 번까지 보내며, 무엇을 절대 보내지 않는지를 정의한다.

1원칙

알림을 설계할 때 지키는 네 가지
원칙내용
강제하지 않는다서비스 원칙상 행동 이행을 압박하는 알림은 만들지 않는다. "아직 안 하셨어요", "연속 기록이 끊겨요" 같은 미이행 압박 문구를 쓰지 않는다. 알림은 "준비됐다"와 "남아 있다"만 말한다.
하루에 적게정기 알림(건강 관리 리마인드)은 하루 최대 1회. 서비스 알림(공지사항)은 드물게, 운영자가 등록했을 때만 보낸다.
이미 봤으면 보내지 않는다알림이 가리키는 것을 사용자가 이미 앱에서 확인했으면 보내지 않는다. 발송 직전에 조건을 다시 확인한다.
밤에는 보내지 않는다건강 관리 리마인드는 22시부터 다음 날 8시 사이에 보내지 않는다. 공지사항은 운영자가 지정한 시각을 따른다(§3.2).

2알림 유형

하루 알림 2종과 서비스 알림 1종. 알림 설정은 전체 켬/끔 스위치 하나이며 유형별로 나누지 않는다(§6.1)

2.1 하루 알림

유형보내는 조건시각하루 상한
오늘의 질문그날 아직 홈에 들어오지 않았고, 답하지 않은 문항이 있을 때. 첫 진입 전에는 질문 세트가 만들어지지 않았으므로 "오늘 질문이 준비됐다"는 뜻으로 보낸다. 식사 문항의 첫 끼니 경계가 12시이므로 알림을 보고 12시 전에 들어오면 어제 저녁을 묻는다(식이 질문·목표 상세기획 참조)오전 1회 (11시)1회
건강 관리 리마인드그날 생성된 목표 중 완료하지 않은 것이 있을 때. 목표가 하나도 없는 날(질문에 답하지 않아 잠긴 날)에는 보내지 않는다저녁 1회 (기본 20시)1회

오늘의 질문과 건강 관리 리마인드는 서로 다른 시간대에 각 1회씩이라 합쳐서 하루 2회를 넘지 않는다. 저녁에 질문이 남아 있어도 저녁에는 질문 알림을 따로 보내지 않는다. 질문에 답하지 않은 날은 목표가 잠겨 리마인드 조건도 성립하지 않으므로, 결과적으로 그날은 오전 알림 1회로 끝난다.

2.2 서비스 알림

유형보내는 조건시각
공지사항서버 점검, 앱 업데이트 필수, 정책 변경처럼 운영자가 등록한 공지. 같은 공지는 1회만 보낸다운영자가 지정

현재 버전은 무료로 배포하므로 이용권 만료·결제·환불 알림은 두지 않는다. 유료 전환 시 결제환불정책에 따라 추가한다. 마케팅·이벤트 알림은 이 문서의 범위 밖이며, 도입하려면 별도 동의 항목과 정책이 필요하다.

2.3 만들지 않는 알림

  • 목표 미완료를 재촉하는 알림, 연속일수가 끊긴다는 알림
  • 컨디션 지표가 주의 구간이라는 알림(지표는 앱 안에서만 보여준다)
  • 며칠 접속하지 않았다는 복귀 유도 알림(§8 확인 필요)
  • 걸음 수·수면 등 기기 데이터 달성 알림
  • 끼니마다 보내는 식사 확인 알림

3발송 규칙

조건이 성립해도 보내지 않는 경우와 시각 처리

3.1 발송 직전 재확인

예약된 시각에 무조건 보내지 않고, 보내기 직전에 조건을 다시 확인한다. 조건이 사라졌으면 그 알림은 버린다(미루지 않는다).

유형보내지 않는 경우
오늘의 질문이미 오늘 홈에 들어왔음 · 알림 시각 기준으로 오늘(새벽 4시 이후) 첫 진입이 있었음 · 건강 데이터 미연동이라 질문 세트를 만들 수 없음
건강 관리 리마인드목표 3개를 모두 완료함 · 오늘 생성된 목표가 없음 · 저녁 알림 시각 이후 이미 홈에 들어와 있음(앱이 켜져 있으면 알림 대신 화면으로 충분)

3.2 시각 처리

  • 모든 시각은 기기의 현지 시각 기준이다.
  • 공지사항은 야간 금지 시간을 적용하지 않고 운영자가 지정한 시각에 그대로 보낸다.
  • 아침·저녁 정기 알림의 시각은 기본값을 두되 사용자가 바꿀 수 있게 할지는 §8에서 결정한다.
  • 알림의 하루는 세션 날짜(새벽 4시 경계)를 쓴다. 오전 알림의 "오늘 첫 진입" 판정과 하루 상한 세기가 모두 이 기준이다. 기기 데이터가 쓰는 실제 날짜(자정 경계)와는 다른 값이니 혼동하지 않는다.

3.3 중복과 묶음

  • 같은 유형의 알림은 이전 것이 남아 있으면 새 것으로 교체한다(알림 트레이에 같은 유형이 두 개 쌓이지 않게).
  • 같은 시각에 서비스 알림과 정기 알림이 겹치면 서비스 알림을 먼저 보내고 정기 알림은 5분 뒤에 보낸다.

4문구 규칙

한 줄, 사실만, 압박 없이
  • 제목 없이 본문 한 줄. 30자 안팎.
  • "준비됐어요", "남아 있어요", "끝났어요"처럼 상태를 말한다. "하세요", "잊지 마세요", "놓치지 마세요"처럼 지시·경고하지 않는다.
  • 수치·지표 구간·질문 내용·검진 항목명을 넣지 않는다.
  • 이모지는 쓰지 않는다.
유형기본 문구쓰지 않는 예
오늘의 질문오늘의 질문이 준비됐어요.오늘 질문에 아직 답하지 않았어요 / 수면 상태를 알려주세요
건강 관리 리마인드자기 전까지 오늘의 목표를 실천할 수 있어요.활동 목표를 완료하세요 / 연속 5일이 끊겨요
공지사항운영자가 등록한 문구. 한 줄 원칙은 같되 점검 일시처럼 필요한 정보는 넣는다이모지 · 느낌표 · "꼭"

저녁(18시 이후)에 나가는 문구도 별도 저녁형을 두지 않는다. 정기 알림은 시각이 고정돼 있어 시간대별 문구가 필요 없다.

앱 업데이트 안내는 새 기능을 소개하면 광고성 문구로 보일 수 있다. "무엇이 추가됐는지"가 아니라 "왜 업데이트가 필요한지"만 담는다. 예: "일부 기기에서 알림이 늦게 오는 문제를 고쳤어요"(O) / "새로워진 홈 화면, 지금 만나보세요"(X)

6수신 설정과 권한

앱 설정 · OS 권한 · 둘의 관계

6.1 앱 안의 알림 설정

계정 > 알림 설정에는 "알림 받기" 스위치 하나만 둔다. 유형별 스위치는 두지 않는다. 켜면 §2의 모든 알림을 받고, 끄면 어떤 알림도 보내지 않는다. 기본값은 켬.

스위치 아래에 받게 되는 알림을 한 줄로 안내한다: "오늘의 질문 · 건강 관리 리마인드 · 공지사항". 그 아래에 "하루 2회를 넘지 않고, 밤 10시부터 아침 8시까지는 보내지 않아요"를 둔다.

유형별로 나누지 않는 이유: 알림이 세 종류뿐이고 모두 하루 한두 번 수준이라 골라 끌 만큼 많지 않다. 스위치가 하나면 "끌 수 없는 알림"이라는 예외를 둘 필요도 없어 규칙이 단순해진다. 유형별 선택이 필요해지면 그때 나눈다.

6.2 OS 알림 권한

① 요청 시점온보딩의 접근 권한 안내 화면(카메라 · 알림)에서 "확인"을 누른 직후, 카메라 권한에 이어 OS 알림 권한 창을 띄운다. 접근 권한 사전 고지 기능과 같은 흐름이며 별도 요청 시점을 두지 않는다
② 사전 안내접근 권한 안내 화면의 알림 항목 설명이 사전 안내 역할을 한다. 설명 문구는 "오늘의 질문 · 남은 목표 · 공지사항"으로, 현재 시안의 "서비스 안내, 추천 등"은 이 정책의 유형에 맞게 바꾼다
③ 거부 시앱은 정상 동작하고 알림만 오지 않는다. 앱 안 알림 목록(§7)에는 기록이 남는다. 다시 묻지 않고, 알림 설정 화면에 OS 설정으로 가는 안내만 둔다

6.3 두 설정의 관계

OS 권한앱 설정결과
허용켬발송
허용끔발송 안 함. 앱 안 알림 목록에도 남기지 않는다(사용자가 끈 것)
거부켬발송 안 함. 앱 안 알림 목록에는 남긴다. 설정 화면에 "휴대폰 설정에서 알림이 꺼져 있어요" 안내
거부끔발송 안 함, 기록 안 함

앱 설정 끔은 모든 유형에 똑같이 적용된다. 공지사항처럼 알림을 껐어도 알아야 할 내용은 앱 안 공지 화면에서 볼 수 있으므로 알림으로 강제하지 않는다.

7알림 목록 (앱 안)

홈 헤더의 알림 아이콘으로 여는 화면. 현재 IA에서 "준비 중"인 항목의 최소 정의

7.1 구성

  • "오늘"(새벽 4시 이후 받은 것)과 "지난 메시지"(그 이전 30일) 두 구역. 30일이 지난 항목은 지운다. 오늘 항목이 없으면 오늘 구역을 숨긴다.
  • 카드 = 유형 아이콘 · 유형명 · 받은 시각 · 본문(푸시와 같은 문구). 유형명은 §2의 이름과 같게 쓴다. 누르면 §5와 같은 화면으로 이동한다.
  • 읽지 않은 카드는 본문을 굵게, 읽은 카드는 보통 굵기로. 읽지 않은 수를 홈 헤더 알림 아이콘에 표시하고, 목록 화면을 열면 모두 읽음 처리한다.
  • 받은 시각은 상대 표기: 1분 미만 "지금", 1시간 미만 "n분 전", 오늘 "n시간 전", 어제 "어제", 7일까지 "n일 전", 그 이후 날짜.
  • 비어 있으면 "받은 알림이 없어요" 한 줄.

7.2 기록 규칙

  • 실제로 발송된 알림과, OS 권한 거부로 발송되지 못한 알림을 기록한다. 앱 설정에서 알림을 꺼 둔 동안의 알림은 기록하지 않는다(§6.3).
  • 발송 직전 재확인에서 버려진 알림은 기록하지 않는다(조건이 사라진 알림이므로).
  • 같은 유형으로 교체된 알림(§3.3)은 최신 것만 남긴다.

8확인 필요 사항

이 문서 확정 전 담당자 결정이 필요한 항목
#항목내용상태
1정기 알림 시각 변경오전 11시 · 저녁 20시 기본값을 사용자가 바꿀 수 있게 할지. 허용하면 야간 금지 시간(22~8시)은 선택할 수 없게 막는다. 오전 알림은 식사 문항의 첫 끼니 경계(12시) 전에 들어오게 해야 하므로 12시 이후를 선택할 수 없게 한다확인 필요
